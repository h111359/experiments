Q-block Convention (normative)
Aliases: $AB=@aib-analyze.md | $IM=@.aib_memory/input.md | $QSEC=## Questions | $QID=Q<nnn>
Purpose: canonical Q-block format spec for decision points tagged ask; single source truth for structure; $AB MUST reference this file for format rules.
Scope:
 applies_to: [all Q-blocks generated by $AB + written to $IM, all questions presented by aib-clarify.md + recorded in .aib_memory/clarification_questions.md, both formats: multiple-choice + free-text]
 out_of_scope: [format selection guidance, generation triggers, classification rules, Answer Application Sub-flow] -> see $AB
Normative language: MUST/MUST NOT/SHALL/SHOULD/MAY => BCP14 (RFC2119/RFC8174).
QID rules:
 format: $QID (3-digit zero-padded; ex: Q001,Q002)
 sequence: start Q001; +1 sequential
 existing_questions: [if $IM $QSEC already has QIDs] -> continue next available
 immutability: written QID !reused && !reassigned
Multiple-choice template:
 **Q<nnn>**: <question text>
 > **Why this matters:** <one-sentence implementation impact>
 - [ ] Option A: <text> *(recommended)*
 - [ ] Option B: <text>
 - [ ] Option C: <text>
 - [ ] Other: ___
Multiple-choice rules:
 order: Why-this-matters line immediately after question text && before options
 options_count: min 2 [Option A, Option B]; prefer >=3 [A,B,C,...]
 required_option: Other: ___
 recommendation: exactly 1 option marked *(recommended)*; AI MUST mark the preferred option first; all others !marked
 option_prefix: each option line MUST start `- [ ] ` (exact chars)
Free-text template:
 **Q<nnn>**: <question text>
 > **Why this matters:** <one-sentence implementation impact>
 - Answer: ___
Free-text rules:
 order: Why-this-matters line immediately after question text
 answer_line: exact `- Answer: ___`
 question_text: MUST state [info needed, why needed, implementation impact]

Clarification-history rules (aib-clarify.md only):
 active_file: .aib_memory/clarification_questions.md
 creation: create directly on first question, including before a request exists; no script execution
 persistence: read existing content before changes; append questions when presented and responses when received; verify saved content before the dependent workflow step
 history: preserve all prior content across rounds and subsequent executions until request archival; no migration of prior clarification answers
 identifiers: start Q001 when no existing QIDs; continue above the highest QID in active clarification history or $IM $QSEC; never reuse or reassign IDs within the accumulated history
 question_record: append the exact Q-block, including full wording, Why-this-matters line, all offered options, exactly one recommended marker for multiple-choice, and Other/free-text alternatives
 unanswered: all question options remain unchecked and Answer stays ___; append `Status: Unanswered`; recommendations are never user responses
 response_record: append `### Q<nnn> — Response <n>` with per-question sequence starting at 1; include the exact user response, selected options and free-text explanations, and links to multipart question parts
 revisions: append the next numbered response with `Supersedes: Q<nnn> — Response <previous n>`; preserve earlier responses and the original question; the highest response number is the latest answer, never an overwrite
 ordering: append events in presentation/reception order; QID plus response number unambiguously links each response to its question
 unresolved_response: preserve raw response under `### Unresolved response <n>` when its QID mapping is ambiguous; append a later mapping to the original event once the user clarifies it; do not infer selected options or answers
 resume: reconcile the conversation with existing question and response records; do not append an already recorded event merely because context was reread or execution resumed
 failure: report the failing path and error; stop the dependent presentation, answer-application, or proposal step until persistence succeeds
 lifecycle: request creation, analysis, input archival and reset leave active history intact; log-convention.md defines request-artifact archival and recovery
