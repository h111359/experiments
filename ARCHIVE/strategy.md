# D&A Strategy

## Overview

GDATD team ideas about the vision, strategy and principles of Data and Analytics area in TCCC

## Strategy Elements


### Products

- **Global Data Products Catalogue** - centralized place where everyone in the company can discover the data products, the business and technical owners and how to receive access
- **AI Ready Documentation** - detailed domain and technical documentation related to the products and stored in AI readable format
- **Knowledge Internalization** - the know how, ability to decide, ability to control is based on knowledge kept internally  

### Teams

- **Technical Ownership** - each product has a single team which is it technical owner
- **Own Way of Work** - teams are independent in deciding their way of work, principles, roles and positions   
- **DevOPS Model** - Development, Operations, Production Management, Services - all covered by the technical owning team
- **Extendable** - the teams can be extended with external resources but should remain in control

### Governance

- **Data Owners Assignment** - each data area should have appointed data owner, responsible for the data linage, quality, access, certification  
- **Centralized Infra Owner** - the company infrastructure should be managed by a single organization to be guaranteed common standards and processes
- **Aligned Product Roadmaps** - involvement of the users of data product in prioritization and requirements gathering  

## Data
- **Wholistic Data Catalogue** - data should be discoverable in catalogue(s) describing the semantic, the data model, ownership and responsibility, confidentiality and the location of the data
- **Quality Certification Process** -   

**Standards**  
- Architecture Templates  
- Shared Codebase  

## Strategy Elements Details


## Data

---

### Certification
- A process of formal certification of the data should be established
- If the data is not marked as certified, the data should not be treated as a source of truth
- On the other hand – the certified data should be trusted

---

### Code Repositories
- All the production programming code should be shared in GitHub repositories
- The repositories should comply with specific rules established by the D&A TEC guaranteeing good code quality, reusability and documentation

---

## Infrastructure and Tools

### Tools Catalogue
- We follow Azure first choice principle. There should be created a catalogue of approved tools – both cloud based or local machine tools, which should be used, mastered by the employees and purchased and installed by default according the roles

---

### Architecture Templates
- Template pre-approved architecture with the recommended services
- Possible variations to be clarified
- Still the technical team should be able to propose custom solution for corner cases

---

### Centralized Infra Owner
- The Azure infrastructure for data products to follow the same standards as for the rest of the products
- Data and Analytics community should not be responsible for infrastructure management and support
- Maintenance and support should be delegated to the Cloud team(s)

---

### Sandbox Environments
- Each team should be equipped with a sandbox environment for training, experimentation and ideation fostering new ideas and creativity boost
