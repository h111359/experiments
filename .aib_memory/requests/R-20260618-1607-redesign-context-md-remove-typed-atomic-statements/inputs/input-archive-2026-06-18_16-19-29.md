## Input

Need a structural redesign of the context.md document model within the AIB framework, specifically targeting the removal of typed atomic statements and replacing them with a simplified, uniform representation to improve efficiency and reduce token consumption.
Currently, context.md enforces a strict atomic statement syntax where each entry is prefixed with a type identifier (e.g., Requirement, Decision, Constraint) expressed as a single-letter code (R, D, C, etc.) followed by a colon and statement text. 
This typed structure supports semantic classification, validation rules, and tool-based operations such as CRUD manipulation and format verification. [onedrive.c...a-cola.com]
The requested change replaces this model with a type-less statement format, defined as:
- <text>

where:

Each statement remains a single atomic bullet line
The type prefix is fully removed
No alternative semantic encoding (inline tags or metadata) is introduced

Under this new model, all semantic meaning previously encoded in statement types is intentionally discarded, and no equivalent classification mechanism is retained. As a result:

Statements are treated as plain, context-bearing facts
No distinction exists between requirements, decisions, constraints, or informational statements
All interpretation responsibility shifts to the consuming AI or human reader

To compensate for the removal of type-level semantics, the user explicitly defines that existing area sections (e.g., Functionality, Technical Design, Security) become the sole structural and organizational mechanism.
These areas implicitly group related statements and serve as the only remaining layer of contextual segmentation.
The change is intended to be applied as a global, breaking transformation, meaning:

The existing context.md file in `.aib_memory` must be migrated to the new format
No backward compatibility with the typed format is required or maintained
Mixed-format coexistence is explicitly excluded

Existing tooling (verify-context.py, edit-context.py) MUST be updated to support the new format
Validation MUST remain strict and deterministic, but adapted to the simplified syntax
Operational capabilities (such as statement uniqueness enforcement and targeted modifications) must be preserved despite removal of type identifiers

The underlying motivation for this redesign is twofold:

Token Efficiency: reducing verbosity of statements by eliminating type prefixes and associated structural overhead
Processing Efficiency: simplifying context representation to streamline parsing and interpretation by AI systems

The expected result is a leaner, more compactcontext.md, optimized for:

Lower token usage during prompt execution
Faster comprehension by AI models
Reduced structural complexity while preserving sufficient organization through area-based grouping
