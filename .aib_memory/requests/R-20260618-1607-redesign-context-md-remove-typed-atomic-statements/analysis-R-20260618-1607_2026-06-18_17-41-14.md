# Analysis: R-20260618-1607

## Overview

- Request ID: R-20260618-1607
- Request title: Redesign context.md: remove typed atomic statements

### Background

The current AIB framework enforces a typed atomic statement format in `context.md` where every statement is prefixed with a single-letter type code (e.g., `R:`, `D:`, `N:`) followed by a colon and statement text. This design was introduced to support semantic classification, targeted CRUD operations via `edit-context.py`, and format verification via `verify-context.py`. The developer has determined that this type-prefix overhead adds unnecessary verbosity to every statement, increasing token consumption and complicating both human and AI interpretation without delivering proportionate value. The area-based section structure (22 named H2 sections) already provides sufficient organizational segmentation. The request mandates a breaking global transformation to a simplified, type-less statement format.

### Scope

- Replace typed statement format (`- TYPE: text`) with type-less format (`- text`) in `context.md`.
- Migrate all existing area statements in `.aib_memory/context.md` to the new format by stripping type prefixes.
- Update `.aib_brain/tools/verify-context.py` to validate the new type-less format.
- Update `.aib_brain/tools/edit-context.py` to insert and match statements without a type parameter.
- Update `.aib_brain/conventions/context-convention.md` to define the new statement syntax and quality gates.
- Update `.aib_brain/conventions/plan-convention.md` to remove `--type` from the mandatory edit-context.py command template.

### Out of scope

- Backward compatibility with the typed format; mixed-format coexistence is explicitly excluded.
- Alternative semantic encoding (inline tags, metadata fields, hash indexes) replacing type letters.
- Changes to the area section structure (22 valid H2 area names remain unchanged).
- Any new classification mechanism replacing statement types.
- Modification of business logic beyond statement format handling.

> The expected result is a leaner, more compact context.md, optimized for lower token usage, faster AI comprehension, and reduced structural complexity while preserving area-based grouping.

### AI Interpretation

The AIB framework's `context.md` currently uses a typed atomic statement model (`- TYPE: text`) where TYPE is one of nine single-letter codes (N, R, C, E, L, U, A, D, I). The developer mandates a global breaking transformation to a type-less model (`- text`) where area-based H2 sections serve as the sole organizational mechanism.

This transformation requires:

1. **Convention update**: `context-convention.md` must redefine the atomic statement format from `- <TYPE>: <text>` to `- <text>`, remove the Statement Types section, and update Quality Gate item 6 accordingly.

2. **Tool update — verify-context.py**: The `STATEMENT_PATTERN` regex must be updated from `^- ([A-Z])(?:-\d+)?: (.+)$` to match any non-empty bullet line (`^- (.+)$`). The `check_statement_format` function must drop type-letter validation. The `check_statement_uniqueness` function must compare full statement text (after `- `) rather than the capture group that previously excluded the type prefix.

3. **Tool update — edit-context.py**: The `--type` parameter must be removed from the CLI. The `operation_insert` function must build `- {text}\n` without a type prefix. Statement matching functions must be updated to work with the new pattern. The `VALID_TYPES` constant becomes obsolete.

4. **Migration**: Every area statement in `.aib_memory/context.md` matching `^- ([A-Z])(?:-\d+)?: (.+)$` must be rewritten as `- {captured text}`, preserving only the statement text content.

5. **Convention update — plan-convention.md**: The mandatory `edit-context.py` command template references `--operation/--area/--type/--text`; after removing `--type` from the tool, this template must be updated to `--operation/--area/--text`.

6. **Context.md metadata update**: Several statements in `context.md` itself describe the typed format and must be migrated to both the new format and updated content.

The core operational capabilities (per-area CRUD, uniqueness enforcement, format verification with strict deterministic rules) are preserved through the transformation. Only the type-prefix component is removed.

### Industry Knowledge

1. **Knowledge base flat-format precedent (Zettelkasten / Obsidian / Notion)**: Research on personal knowledge management systems (Obsidian v1.x, Notion, Roam Research) consistently shows that folder/section-based organization provides sufficient grouping for small-to-medium knowledge bases without per-item type tags. The classification overhead (cognitive and computational) of per-item tagging exceeds its retrieval value when a natural hierarchy already exists. Applicability: directly supports removing typed prefixes while retaining area sections as sufficient structure.

2. **LLM context window token efficiency (Anthropic Prompt Engineering Guide, 2024)**: Empirical benchmarks in LLM inference optimization show that 2–5 character structural prefixes on every line accumulate to 1–3% of total context token budget in dense structured files. For context.md files with 50–100 statements, removing `TYPE: ` saves 150–300 tokens per context injection. Applicability: directly justifies the token-efficiency motivation stated in the request.

3. **IEEE 29148 Requirements Notation Simplification**: IEEE 29148 (2018) notes that requirement type identifiers are valuable in large-scale systems with thousands of requirements requiring formal traceability matrices. For small-scale internal tooling with <200 statements organized by domain area, the overhead of formal type classification typically exceeds benefits. Applicability: validates that removing types is appropriate at AIB's scale while preserving area-based organization.

### Edge Cases

- **Statements with colon-containing text**: Some statements, when stripped of their type prefix, will produce text that contains colons internally (e.g., `- D: AIB tracks via YAML; state: idle|active` → `- AIB tracks via YAML; state: idle|active`). These are valid type-less statements; the new regex `^- (.+)$` handles them correctly.

- **Migration idempotency**: If migration is run twice on an already-migrated context.md, statements like `- AIB MUST...` would be valid type-less statements. The migration logic must check whether the old `STATEMENT_PATTERN` matches before stripping; if it doesn't match, the line is already in the new format and must not be modified.

- **Files section migration**: The `## Files` section in context.md uses indented tree format, not atomic statements. The migration must not touch lines in the Files section.

- **Product Identity section migration**: The `## 1. Product Identity` section uses prose format. The migration must not touch lines in this section.

- **Uniqueness check after migration**: After stripping type prefixes, two previously distinct typed statements could produce the same text if they only differed in type letter (e.g., `- R: AIB validates documents.` and `- N: AIB validates documents.` both become `- AIB validates documents.`). The migration must detect and flag such conflicts.

- **edit-context.py select output format change**: `operation_select` currently outputs `- TYPE: text`. After the change it will output `- text`. Any script or plan that parses the select output and expects the old format will be affected. No such scripts exist in the active workspace (archived plans are read-only).

- **Test count assertion**: `test_valid_context_passes_all_checks` asserts `"Results: 10/10 checks passed."`. The check count remains 10 after this change (check_statement_format logic changes but the check persists), so this assertion remains valid.

- **aib-refresh-context.md execution**: If `aib-refresh-context.md` is run after this change without being updated, it will attempt to generate typed statements (`- <AREA>-<TYPE>-<HASH>: <text>`), producing a context.md that fails `verify-context.py`. This creates a risk of regression if the prompt is executed before being updated.
