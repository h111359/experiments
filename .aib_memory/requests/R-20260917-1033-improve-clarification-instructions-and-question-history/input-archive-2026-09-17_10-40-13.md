## Input

### Goal

Improve `.aib_brain/prompts/aib-clarify.md` so clarification consistently observes workspace instructions and preserves a complete question-and-answer history in `.aib_memory/clarification_questions.md`.

### Workspace Instructions

- Before gathering context, read `.aib_memory/instructions.md`.
- Follow the behavior of S01.1 in `.aib_brain/prompts/aib-analyze.md`: when the file exists and is non-empty, execute and observe its applicable directives throughout clarification; when absent or empty, proceed normally.
- Loading instructions must not automatically invoke the analysis or implementation workflow.
- Retain the clarification prompt’s prohibition on running scripts. When a script command is required, provide the exact command for the user to execute, using `python -B` or `python3 -B` for AIB tools.

### Clarification History

- Record every question asked by `aib-clarify.md` in `.aib_memory/clarification_questions.md`.
- Create the file when the first question is recorded.
- Update this file directly without requiring script execution.
- Preserve existing content across clarification rounds and subsequent executions until request archival.
- Record questions when they are presented, including their identifiers, complete wording, implementation-impact explanations, and every offered option, including the recommended option and any free-text alternative.
- Follow `q-block-convention.md` for question formatting and identifier rules.
- Leave unanswered questions explicitly unanswered. Never infer or prefill the user’s answer.
- Record the user’s response when received, preserving selected options and any free-text explanation.
- Preserve earlier answers when the user revises a decision; record the revision so the latest answer and the preceding history are clear.
- Keep questions and responses unambiguously linked and ordered.
- Avoid duplicating existing records merely because the workflow resumes or rereads its context.
- Report persistence failures and stop the dependent workflow step rather than silently continuing without the history.

### Archival Lifecycle

Give the clarification history the same lifecycle as `.aib_memory/log.md`:

- Allow recording before an active request exists.
- Preserve the history through request creation, analysis, input archival, and input reset.
- Archive the complete accumulated history alongside the runtime log using the existing request-artifact archival workflow.
- Use `clarification_questions_<request_id>.md` as the archived filename.
- After successful archival, leave `.aib_memory/clarification_questions.md` present and empty.
- Preserve existing archive content when additional entries are archived.
- Follow the runtime log’s durability, retry, and recovery behavior.
- If clarification-history archival fails, keep the request active and preserve recoverable content.
- Handle requests with no clarification history without failing.
- Repeated archival calls must not duplicate successfully archived content during normal execution.

Update the supporting archival tools and conventions as necessary to implement this behavior.

### Workflow Changes

- Remove step 7, “Save questions and answers.”
- Remove the instruction to save clarification questions and answers under `### Clarification Questions` in `input.md`.
- Integrate history recording into the question-presentation and answer-reception steps.
- Renumber the remaining workflow steps and update affected references.
- Retain the final copy-paste-ready proposal for replacing the `## Input` content, using only headings at level 3 or below.

### Acceptance Criteria

- Existing, empty, and missing workspace-instruction files receive the specified handling.
- Multiple clarification rounds preserve every question, option, answer, and revision.
- Clarification history survives analysis-time input reset.
- Request archival preserves the history and empties the active file.
- Missing history, repeated archival, and archival failure follow the specified behavior.
- Relevant automated checks cover archival integration and failure handling.
- Affected framework documentation describes the resulting behavior.

### Scope Boundary

This request covers the clarification prompt and supporting history persistence, archival, tests, and documentation. It does not introduce question logging for other prompts or migrate previously recorded clarification answers.
