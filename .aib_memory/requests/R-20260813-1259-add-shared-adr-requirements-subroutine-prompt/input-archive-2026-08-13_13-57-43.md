### Detailed Requirements

#### 1. New subroutine prompt `.aib_brain/prompts/aib-update-adr-requirements.md`
- Title `# Prompt: aib-update-adr-requirements`.
- States it is a subroutine invoked by `aib-implement.md`, `aib-modify.md`, and `aib-execute.md`.
- Takes as input from the calling prompt: (a) the caller identifier used to pick the activity tag (`[A]`/`[D]`), (b) the current `## Input` text and any implementation notes gathered by the caller.
- Reads `.aib_memory/adr.md` and `.aib_memory/requirements.md`; lazily creates them if absent (empty file).
- Extracts new user requirements from `## Input` and appends one row per new requirement to `requirements.md`.
- Extracts new architecture/design decisions the caller made that are NOT visible from other workspace files and appends one row per decision to `adr.md`.
- Applies the row schema, UTC timestamp, and provenance tag mapping defined above.
- Applies the normalized-text dedup rule against all existing rows in the target file (any tag) before appending.
- On any I/O or write failure: retry ONCE immediately; on second failure, HALT the calling prompt with a clear error and DO NOT proceed to close.
- MUST NOT modify or delete any existing row.
- MUST NOT append rows to any file other than the two target files.
- References `.aib_brain/conventions/adr-requirements-convention.md` as the authoritative schema.
- Emits one `log-entry.py` line at start and at successful end of the subroutine.

#### 2. New convention `.aib_brain/conventions/adr-requirements-convention.md`
- Normative language block (BCP 14).
- Purpose: append-only history of user requirements and architecture decisions across the request lifecycle.
- Row schema (verbatim): `- [YYYYMMDD-HHMMSS-<request_id>] [<TAG>] <text>`, one row per line, UTF-8 Markdown.
- Activity tag registry: `[A]` (active), `[D]` (deprecated); new tags require a convention update.
- Timestamp MUST be UTC in the `YYYYMMDD-HHMMSS` format.
- Dedup: normalized-text match on `<text>` (collapse consecutive whitespace, case-insensitive) across the whole file, all tags.
- Failure semantics: retry once, then halt caller.
- Files MUST remain append-only; rewriting or deleting historical rows is PROHIBITED.
- Referenced exclusively by `.aib_brain/prompts/aib-update-adr-requirements.md` and the three caller prompts.
