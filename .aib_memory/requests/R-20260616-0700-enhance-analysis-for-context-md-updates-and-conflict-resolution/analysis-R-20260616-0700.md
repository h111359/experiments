# Analysis: R-20260616-0700 - Enhance analysis for context.md updates

## Overview
The objective is to modify the AI Builder analysis process to explicitly analyze required changes to `context.md` during the analysis phase, prior to plan generation. This ensures conflicts are identified, intent is preserved, and resolutions are premeditated.

## Input Interpretation
- **Target:** `aib-analyze.md` and `analysis-convention.md`.
- **Requirement 1:** Add a new structural step/section in `analysis-convention.md` specifically named "Context Update Analysis".
- **Requirement 2:** Ensure this section analyzes identifying conflicts with existing context, preserving original intent, and resolving them.
- **Requirement 3:** Update `aib-analyze.md` to instruct the LLM to correctly populate this new section during step S05.

## Research Results
- **Current State of `aib-analyze.md`:** Context update generation is currently deferred entirely to `S09. Step 9 — Plan Generation` (specifically S09.2), where exact `edit-context.py` commands are drafted. There is no dedicated reasoning step for context conflict resolution during S05.
- **Current State of `analysis-convention.md`:** Lacks a dedicated section for evaluating context impact.
- **Risks:** 
  - Without dedicated context analysis, the planner agent in S09 might blindly overwrite existing context elements, destroying historical intent.

### Requirements Gate Evaluation
Requirements Gate: 8/8 PASS — all categories satisfied.

## Proposed Solution

### High-Level Concept
Introduce a explicit `## Context Update Analysis` section into `analysis-convention.md` and update `aib-analyze.md`'s S05 sequence to populate it, moving the cognitive load of conflict resolution out of the planner and into the analyst.

### Execution Steps
1. Modify `.aib_brain/conventions/analysis-convention.md` to insert a new mandatory section `## Context Update Analysis` (placed after `## Proposed Solution` and before `## Decision Register`).
2. Define the sub-structure for this new section: Context Elements to Add, Context Elements to Modify/Remove, Conflict Resolution, and Intent Preservation.
3. Modify `.aib_brain/prompts/aib-analyze.md` at step `S05` to explicitly require populating the `## Context Update Analysis` section.
4. Update `S09.2` in `aib-analyze.md` to reference the newly created analysis section when generating the `edit-context.py` commands.

### Files to be Modified
- `.aib_brain/conventions/analysis-convention.md`
  - Insert the `## Context Update Analysis` section definition.
- `.aib_brain/prompts/aib-analyze.md`
  - Update S05 rules to enforce the new section.
  - Update S09 rules to pull context update logic from the new section.

### Why this approach?
Separating the *reasoning* about context changes (conflict detection, intent preservation) from the *planning* of context changes (exact command syntax) adheres to the reasoning-first workflow. It prevents context corruption by forcing the LLM to justify modifications before drafting the execution plan.

## Decision Register

### Decision Points
- **DP-1: Placement of Context Update Analysis section**
  - **Alternative A (Chosen):** Place as a top-level section `## Context Update Analysis` immediately following `## Proposed Solution`.
  - **Alternative B:** Place as a sub-section `### Context Update Analysis` inside `## Proposed Solution`.
  - **Rationale:** Context updates are a workspace-wide operational requirement distinct from the product solution itself. A top-level section provides better visibility and strict schema validation. Tag: `resolve-autonomously`.
