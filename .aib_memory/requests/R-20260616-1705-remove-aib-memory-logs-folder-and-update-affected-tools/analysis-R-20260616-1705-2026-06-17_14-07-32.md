# Analysis — R-20260616-1705

## Overview

**Request ID:** R-20260616-1705

**Request Title:** Remove .aib_memory logs folder and update affected tools

### Background

The AIB workspace currently includes a `.aib_memory/logs/` directory that `menu.py` auto-creates when executing actions, writing timestamped `.log` files capturing command output. The developer wishes to stop this log-file generation and remove the folder, simplifying the workspace by eliminating transient files that add clutter without providing durable value.

### Scope

- Remove creation of `.aib_memory/logs/` from `initialize.py` (standard init and upgrade re-seed paths).
- Remove or modify the log-file writing machinery in `menu.py` (`_make_log_path`, `_stream_pipe`, `_run_and_tee`, `run_action`).
- Update tests in `test_initialize.py` and `test_menu.py` that assert the existence of `.aib_memory/logs/` or test log-file writing behaviour.
- Update `test_user_guide_product_accuracy.py` test `test_sc4_logs_described_as_tool_execution` that checks the user guide describes `.aib_memory/logs/` as "Tool execution and action logs".
- Update `user_guide.html` directory-structure listing that shows `logs/` under `.aib_memory/`.
- Update `.gitignore` entry that ignores `.aib_memory/logs/aib-action-*.log`.

### Out of Scope

- The root-level `logs/` directory (CI per-version release logs and `next_version_changes.md`) is entirely unaffected by this request.
- No changes to `.aib_brain/prompts/` prompt files — no prompt references `.aib_memory/logs/`.
- No changes to `scripts/release_bookkeeping.py` or CI workflows.
- No changes to context.md — it contains no statement referencing `.aib_memory/logs/`.

### Industry Knowledge

- **Separation of concerns in CLI tooling (UNIX philosophy):** Long-standing practice in tools like GNU Make, npm, and Cargo distinguishes between transient build artefacts (ignored via `.gitignore`) and durable workflow artefacts (committed). Execution logs are typically transient; removing them from managed workspace state reduces maintenance burden. *Applicability: high — the AIB menu logs are transient and not consumed by any downstream AIB step.*

- **Test hygiene — delete tests for removed code (XP, Google Testing Blog):** When production code is deleted, its dedicated unit tests are dead code. Retaining them creates a false sense of coverage, confuses contributors, and can mask future regressions. The established practice is to delete tests that exist solely to verify removed behaviour and, optionally, repurpose tests that validate still-relevant surrounding behaviour. *Applicability: high — `test_creates_logs_folder`, `test_creates_logs_folder_idempotent`, and `TestMakeLogPath` tests exclusively cover the to-be-removed log-directory creation.*

- **Documentation-as-code accuracy (Diátaxis, Write the Docs):** Reference documentation (user guide, README) must reflect the actual structure of the product. Leaving a stale entry for a directory that no longer exists misleads users and degrades trust in the documentation. *Applicability: high — `user_guide.html` line 631 documents `.aib_memory/logs/` and must be updated.*

### AI Agent Critique

- `initialize.py` creates `logs/` and `requests/` as the only named subdirectories of `.aib_memory/`, but also implicitly creates `attachments/`. The directory-creation block mixes concerns (attachments gets a `.gitkeep`, logs does not), which is mildly inconsistent formatting.
- `menu.py` `_stream_pipe` uses `iter(pipe.readline, "")` which is blocking. When the subprocess ends before the thread reads its EOF, the thread blocks until the pipe is closed by `proc.wait()`. This is correct but fragile if the subprocess hangs; the current design has no timeout. This is a pre-existing concern unrelated to this request.
- `TestRunAndTee` tests the log-file writing behaviour of `_run_and_tee`, but do not test that live terminal output is actually produced (they only assert file content). This means terminal-streaming correctness is not tested by existing tests, regardless of whether log files are removed.
- `test_sc4_logs_described_as_tool_execution` is tightly coupled to specific string literals in `user_guide.html`. If any refactoring renames the description, the test will fail without behavioural intent changing. This is brittle but acceptable for accuracy-gate tests.
- The `.gitignore` pattern `.aib_memory/logs/aib-action-*.log` uses a path-specific pattern rather than a directory-level ignore (`/.aib_memory/logs/`). If the directory were empty (no `.gitkeep`), git would not track it regardless. The pattern is therefore redundant once the directory is removed.
- `context.md` `## Files` section lists `.aib_memory/` subdirectories but does not include `logs/` or `archives/` or `attachments/`, making it already inconsistent with the actual workspace structure. Out of scope for this request.

### Edge Cases

- **Upgrade path with existing `logs/` content:** If a workspace was created with an older AIB version that produced log files, running `--upgrade` will archive those logs via `_run_upgrade`'s `shutil.copytree` loop. After upgrade, `_seed_memory` will no longer re-create `logs/`. This is correct self-consistent behaviour.
- **User has manually created `.aib_memory/logs/`:** After this change, AIB will never create or reference the directory, but does not delete it either. A manually-created `logs/` folder will persist silently. This is acceptable; AIB does not police user-created directories.
- **`.gitignore` pattern after removal:** Once `.aib_memory/logs/aib-action-*.log` is removed from `.gitignore`, any stale log files in a developer's working copy (if the directory was tracked before) would become untracked but not ignored. This is a one-time migration concern; running `git rm -r .aib_memory/logs/` would clean it up if needed. Documentation should note this if necessary.
- **`TestRunAndTee` class becomes orphaned if `_run_and_tee` signature changes:** If Decision Point `menu-streaming-approach` results in removing `_run_and_tee` entirely, the entire `TestRunAndTee` class must be deleted. If `_run_and_tee` is kept but without a `log_path` parameter, all `TestRunAndTee` tests must be rewritten to match the new signature.
- **`_make_log_path` import in `test_menu.py`:** Line 20 imports `_make_log_path` directly. If the function is removed, the import must be removed; otherwise tests will fail at collection time with `ImportError`.

### Why this approach?

AIB follows a convention-over-configuration principle and a minimal-footprint philosophy (context.md Concepts): it adds only `.aib_brain/` and `.aib_memory/` to the workspace. Transient execution logs stored in `.aib_memory/logs/` contradict this principle by accumulating files that serve no downstream AIB workflow step (no prompt reads them). Removing them at the source (tool code and initialization) and cleaning up all references is the approach most consistent with AIB's existing design language. All necessary adjustments are confined to a single implementation run, respecting the specification-first constraint.

## Decision Register

### Decision Points

#### Decision Point: menu-streaming-approach

- **Tag:** ask
- **Where it applies:** `menu.py` functions `_make_log_path`, `_stream_pipe`, `_run_and_tee`, and `run_action`; and `tests/test_menu.py` `TestMakeLogPath` and `TestRunAndTee` classes.
- **Why alternatives exist:** `_run_and_tee` currently serves two purposes: live-streaming subprocess output to the terminal AND writing that output to a log file. Removing log-file writing can be done by stripping the file-write logic while keeping streaming, or by replacing the whole function with a simpler subprocess call. The developer's input does not specify whether live streaming must be preserved.
- **Alternative A:** Keep `_stream_pipe` and `_run_and_tee`; remove all `log_file` write calls and the `log_path` parameter. `run_action` calls `_run_and_tee(command, title, inherit_stdin=False)`. `TestRunAndTee` tests are rewritten to test terminal-streaming behaviour only (no log file assertions). `TestMakeLogPath` is deleted.
  - *Benefits:* Live line-by-line streaming to terminal is preserved; long-running scripts show progress in real time.
  - *Drawbacks:* More code to maintain; `_stream_pipe` and threading overhead remain for a terminal-only use case.
  - *Codebase impact:* Moderate — function signatures change; tests rewritten.
- **Alternative B:** Remove `_make_log_path`, `_stream_pipe`, and `_run_and_tee` entirely. `run_action` calls `subprocess.run(command, check=False)` with inherited stdout/stderr (or piped). `TestMakeLogPath` and `TestRunAndTee` classes are deleted.
  - *Benefits:* Simpler code; fewer moving parts; removes threading.
  - *Drawbacks:* For long-running scripts, output is still printed line-by-line when inherited, but buffering behaviour may differ by OS. No structural streaming control.
  - *Codebase impact:* Larger reduction — three functions removed; two test classes deleted; import list shrunk.

#### Decision Point: log-display-line

- **Tag:** ask
- **Where it applies:** `menu.py` `run_action`, line 536: `print(f"Log: {log_path}")`.
- **Why alternatives exist:** This line currently prints the path of the generated log file after action execution. Once log files no longer exist, the line has no replacement content. The developer's input does not specify whether a replacement message is desired.
- **Alternative A:** Remove the line entirely. The status line (`Status: Success` / `Status: Failed (exit code N)`) already communicates outcome; no further output is needed.
  - *Benefits:* Simpler output; no misleading or stale messages.
  - *Drawbacks:* Slightly less verbose post-action summary.
  - *Codebase impact:* Minimal — one line deleted.
- **Alternative B:** Replace with `print("Output streamed to terminal.")` or a similar neutral message.
  - *Benefits:* Maintains the structural feel of the post-action summary block.
  - *Drawbacks:* The message adds no real information if streaming is already visually obvious.
  - *Codebase impact:* Minimal — one line changed.

#### Decision Point: test-upgrade-archive-logs

- **Tag:** ask
- **Where it applies:** `tests/test_initialize.py` `test_upgrade_archive_includes_logs` (lines 128–140).
- **Why alternatives exist:** The test exists to verify that the `logs/` directory is archived during `--upgrade`. Without the logs directory, the test's specific assertion is meaningless, but the broader intent of "the archive includes expected content" remains valid.
- **Alternative A:** Delete the test entirely.
  - *Benefits:* Removes dead test code; no false coverage.
  - *Drawbacks:* Loses the pattern of verifying that directory content is archived.
  - *Codebase impact:* Minimal — one test method deleted.
- **Alternative B:** Repurpose the test to verify that `attachments/` content (or another `.aib_memory/` subdirectory such as `requests/`) is included in the archive snapshot.
  - *Benefits:* Preserves the integration-test pattern; verifies archival of real content.
  - *Drawbacks:* Requires rewriting the test body to use a different directory.
  - *Codebase impact:* Moderate — test body rewritten; still one test method.

#### Decision Point: test-user-guide-sc4

- **Tag:** ask
- **Where it applies:** `tests/test_user_guide_product_accuracy.py` `test_sc4_logs_described_as_tool_execution` (lines 56–64).
- **Why alternatives exist:** The test was added specifically to verify the accuracy of the `.aib_memory/logs/` description in the user guide. Once the entry is removed, the original positive assertion is unsatisfiable, but a negative assertion (confirming absence) could be added.

  - *Benefits:* Provides regression protection against re-introduction of the logs directory in documentation.
  - *Drawbacks:* Fragile string match; adds a negative assertion that is hard to read.
  - *Codebase impact:* Minimal — test body rewritten.

#### Decision Point: user-guide-logs-entry

- **Tag:** ask
- **Where it applies:** `.aib_brain/user_guide.html` line 631 inside the `.aib_memory/` directory listing.
- **Why alternatives exist:** The user guide currently shows `logs/              ← Tool execution and action logs` as a directory under `.aib_memory/`. After this change the directory is no longer created by AIB. The developer's input does not specify the desired final state of the documentation.

  - *Codebase impact:* Minimal — one line updated in `user_guide.html`.
