## Goal

Implement a mandatory, AIB-managed context extension registry and centralize extension reading and updating so supplementary context is deterministic, selectively loaded, and self-healing. The change affects context conventions and verification, data-model extension refresh and validation, initialization and migration, all context-reading prompts, the active workspace context, automated tests, framework documentation, and release bookkeeping.

## Constraints

- Only `context-data-model.md` is introduced in this iteration; additional extension types and a general plugin runtime are out of scope.
- The canonical registry entry heading is `### Context Data Model` and its fields appear in this order: Location, Summary, Convention, Prompt, Read, Update.
- Canonical registry paths are slash-separated and workspace-relative. The fixed values are `.aib_memory/context-data-model.md`, `.aib_brain/conventions/context-data-model-convention.md`, and `.aib_brain/prompts/aib-refresh-context-data-model.md`.
- The fixed Summary is `Logical, physical, and analytical schemas, entities, and relationships discovered in the workspace.`
- AIB owns the heading, Location, Summary, Convention, Prompt, and entry order. Users may change only Read and Update values.
- Read and Update accept case-insensitive `yes` or `no`; managed rewrites normalize them to lowercase. Legacy `true` and `false` values are invalid immediately.
- An extension is loaded only when Read resolves to yes and its Summary is semantically relevant. Missing registered artifacts emit a warning and do not halt the caller.
- Every AIB prompt that reads current `context.md` delegates extension selection to `aib-context-read.md`; that dispatcher must not recursively invoke itself.
- Every Update yes entry is refreshed by executing its registered Prompt during context refresh and after successful implementation.
- `context.md` declarations are authoritative when data-model evidence conflicts. A model may be removed only after an exhaustive workspace scan finds no evidence.
- Data-model identity is the normalized combination of business name and physical Location.
- The canonical no-model extension contains the H1 `# Context Data Model` and the single notice `No data models are currently documented.`; it must not contain model H2 sections.
- Fresh initialization and upgrade create the registry and no-model extension. Idempotent initialization must not overwrite existing Read or Update choices.
- Legacy References conversion occurs in `aib-context-migration.md`; non-extension bibliographic entries are not retained in `## References`.
- Q024's explicit `Update: yes` selection supersedes the earlier prose requesting that the initial flag be turned off.
- All Python tooling uses the standard library, prompts remain model/vendor agnostic, and prompt execution requires no network access.
- Workspace research found no implemented product data model, so the active `.aib_memory/context-data-model.md` starts in the canonical no-model state.
- Stage and commit only request-scoped changes. After the implementation prompt completes its archive and close sequence, create the required one-line implementation commit for `R-20260718-0809` without staging unrelated user changes.

## Success criteria

- `context.md` validation fails when `## References` or the canonical Context Data Model entry is absent, reordered, duplicated, contains an unmanaged entry, or omits a required field.
- Context validation accepts any case variant of yes or no for Read and Update and rejects true or false.
- Fresh initialization and upgrade each create the canonical registry entry and a convention-valid no-model `.aib_memory/context-data-model.md`.
- Re-running initialization preserves an existing context file, extension content, and user-controlled Read and Update values.
- All eight existing context-reading prompts delegate extension loading to `.aib_brain/prompts/aib-context-read.md`; duplicated inline relevance logic is removed.
- Read no skips loading, Read yes still applies semantic relevance, and a missing Location, Convention, or Prompt artifact produces a visible non-blocking warning.
- Context refresh and successful implementation execute the Prompt registered for every Update yes entry and skip Update no entries.
- Data-model refresh preserves context-authoritative models, adds newly evidenced models, removes only models unsupported by an exhaustive scan, produces the canonical no-model state when appropriate, and passes the dedicated validator.
- The active workspace context, README, and user guide consistently document registry ownership, controls, dispatch, migration, initialization, validation, and missing-artifact behavior.
- `python -m pytest tests/`, `python .aib_brain/tools/verify-context.py --workspace .`, and the new data-model validator all exit with code 0.
- `logs/next_version_changes.md` contains appended user-visible bullets and the implementation is committed under a one-line request-scoped commit message.
