## Overview

- Request ID: R-20260718-0809
- Request title: Add managed context extensions

### Background

AIB currently treats context extensions as optional `## References` entries with `Update: true|false`, while context-reading prompts independently repeat semantic-relevance logic. The developer wants a mandatory, AIB-managed extension registry, a shared read workflow, and an initial data-model extension that can be initialized, refreshed, validated, migrated, and documented consistently.

### Scope

The request covers the context and data-model conventions; the context and data-model validators; fresh initialization and upgrade migration; the context refresh, implementation, analysis, modification, clarification, input-from-context, sync-spec, and migration prompts; two new extension prompts; the current workspace context and data-model extension; automated tests; `.aib_brain/README.md`; `.aib_brain/user_guide.html`; and implementation change bookkeeping. It affects AIB users who control extension reads and updates and AIB agents that reconcile, read, and refresh managed extension artifacts.

### Out of scope

Additional extension types beyond `context-data-model.md`, network-backed extension resolution, third-party dependencies, and a general-purpose extension plugin runtime are excluded from this request.

## Input Interpretation

### User Original Inputs

- Make `context.md ## References` mandatory and AIB-managed, with every convention-defined extension registered during initialization.

### AI interpretation

AIB shall treat `## References` as a deterministic registry owned by the framework. The initial `### Context Data Model` entry shall use fixed, separate `Location`, `Summary`, `Convention`, `Prompt`, `Read`, and `Update` lines; only the last two values are user controls. A shared `aib-context-read.md` workflow shall normalize case-insensitive `yes|no` flags, require `Read: yes` plus semantic relevance before loading an extension, and emit a non-blocking warning when a registered artifact is absent.

Fresh initialization and upgrade migration shall create the registry and a convention-valid empty `.aib_memory/context-data-model.md`. Context refresh and migration shall reconcile all managed metadata to convention-defined values while preserving the user's `Read` and `Update` choices. Writable entries shall be refreshed by executing their registered prompt, and the data-model prompt shall exhaustively reconcile workspace evidence, prefer models explicitly named in `context.md` when evidence conflicts, remove a model only when no workspace evidence remains, and validate the result with a dedicated standard-library Python tool. The later Q024 selection of `Update: yes` is treated as the developer's explicit replacement for the earlier prose that requested the flag be turned off.

- Primary users: AIB users choose whether an extension may be read or refreshed; AIB agents own registry structure, discovery, dispatch, reconciliation, validation, and migration.

- Priority assumption: the request is ready now because the existing optional boolean mechanism is already represented in product context but lacks the managed schema, shared dispatcher, initializer, migration, and validator required for reliable use.   - A conforming `context.md` without the managed `### Context Data Model` entry fails validation, while case variants of `yes|no` are accepted and legacy booleans fail.

### Edge Cases

- References is missing, empty, reordered, duplicated, contains a bibliographic entry, or has a renamed managed heading.
- A user edits Location, Summary, Convention, Prompt, or heading while also changing Read or Update; reconciliation must restore managed fields without losing the two user-controlled values.
- Read or Update uses `YES`, `Yes`, or another case variant; consumers accept it and the next managed rewrite persists lowercase.
- Read or Update uses legacy `true|false`; verification rejects it immediately rather than silently migrating it outside the migration prompt.
- Read is yes but Summary is irrelevant; the extension remains unloaded.
- The Location, Convention, or Prompt path is absent; the reading workflow warns and continues without inventing content.
- Update is yes and the registered prompt is absent; refresh warns and continues, while the registry remains intact for repair.
- A workspace contains no data models; the canonical no-model notice validates and contains no fabricated entities.
- Two models share a business name at different locations; they remain distinct. A model moves locations; refresh treats the identity change deterministically and avoids accidental duplication.
- `context.md` names a model but implementation evidence conflicts; the explicit context declaration wins. Absence from one source is not enough to delete a model; all relevant workspace sources must be exhausted.
- A legacy References section contains bibliographic entries, boolean flags, unknown extension headings, or only some managed fields; migration converts supported user flag intent and replaces unsupported entries with the convention-defined registry.
- Refresh is re-run without source changes; ordering and normalized metadata remain stable and no noisy diff is produced.
- The data-model validator is run against a missing file, an empty-state file, a mixed empty/model file, duplicate model identities, invalid headings, or incomplete entity attributes.
- The dispatcher itself reads `context.md`; it must be explicitly exempt from invoking itself to avoid recursion.

## Proposed Solution

### High-Level Concept

Replace the optional extension hints with a convention-defined managed registry and centralize all extension reads and refreshes behind registered prompt metadata. Seed and validate a canonical data-model extension so fresh, upgraded, and existing workspaces follow the same deterministic lifecycle.

### Execution Steps

#### Task 1: Define managed extension contracts

- `.aib_brain/conventions/context-convention.md`: make References mandatory; define the fixed Context Data Model entry, field order, ownership, slash-relative paths, case-normalized `yes|no` controls, deterministic reconciliation, and immediate rejection of booleans and bibliographic entries.
- `.aib_brain/conventions/context-data-model-convention.md`: define model identity as business name plus physical location and add a canonical validator-compatible no-model state.

#### Task 2: Add shared extension workflows

- `.aib_brain/prompts/aib-context-read.md`: add the non-recursive registry reader that normalizes flags, requires Read yes plus Summary relevance, and warns without halting for missing artifacts.
- `.aib_brain/prompts/aib-refresh-context-data-model.md`: add registered-prompt refresh logic for exhaustive workspace reconciliation, context-authoritative conflicts, conservative deletion, empty state, and post-write validation.

#### Task 3: Integrate every context-reading prompt

- `.aib_brain/prompts/aib-analyze.md`: replace inline extension relevance logic with the shared context-read prompt and correct the Proposed Solution subsection count inconsistency while preserving analysis sequencing.
- `.aib_brain/prompts/aib-clarify.md`: invoke the shared context-read prompt in Agent Mode and correct instruction wording defects encountered in the touched workflow.
- `.aib_brain/prompts/aib-context-migration.md`: migrate legacy References to the managed registry, preserve convertible Read and Update choices, create the extension empty state when needed, and invoke shared reads without recursion.
- `.aib_brain/prompts/aib-implement.md`: invoke shared context reads and dispatch every Update yes entry through its registered Prompt after context updates.
- `.aib_brain/prompts/aib-input-from-context.md`: delegate extension selection to the shared prompt and limit planned-entry scanning to sections that allow the tag.
- `.aib_brain/prompts/aib-modify.md`: delegate extension reads and make the context-migration delegation exception consistent with its write and close semantics.
- `.aib_brain/prompts/aib-refresh-context.md`: reconcile the managed registry, delegate reads, dispatch Update yes prompts, preserve Read and Update, and resolve internal write-target, planned-tag, and Done-criteria contradictions.
- `.aib_brain/prompts/aib-sync-spec.md`: replace inline extension relevance logic with the shared context-read prompt.

#### Task 4: Enforce and seed the contracts

- `.aib_brain/tools/verify-context.py`: require the complete fixed registry entry and convention order, reject unmanaged or bibliographic entries and booleans, and accept case-insensitive `yes|no` values.
- `.aib_brain/tools/verify-context-data-model.py`: add standard-library validation for the data-model convention, including canonical empty state, unique model identity, section structure, entities, attributes, relations, and other objects.

#### Task 5: Bring the active workspace onto the new model
