## Input

Change the .aib_brain\user_guide.html to serve as onboarding manual for AIB. It should be more explanatory and provide step-by-step instructions for new users to get started with AIB. The manual should cover installation, configuration, and basic usage of AIB, as well as troubleshooting tips and best practices.

### Goal

Change `.aib_brain/user_guide.html` into a self-contained onboarding manual for new AIB users.

The manual should be more explanatory than the current reference-style guide and should help a first-time user understand what AIB is, how to install it, how to configure it, how to run a first request, and how to use it safely and effectively.

### Target File

- `.aib_brain/user_guide.html`

### Required Layout Change

- Replace the current accordion-style guide with a linear manual-style HTML page.
- Add a persistent left-pane navigation section.
- The left navigation should contain links to the major parts of the document.
- The main content area should be readable as a step-by-step onboarding manual.
- Keep the file fully self-contained:
  - embedded CSS only;
  - embedded JavaScript only if needed for navigation or small usability enhancements;
  - no external network dependencies;
  - no external fonts, icons, libraries, scripts, or stylesheets.

### Installation Coverage

The manual must treat the primary new-user installation path as installation from a versioned AIB archive:

- `versions/aib_brain_vX.Y.Z.zip`

The installation section should explain that the user copies or extracts the versioned `.aib_brain/` archive into the workspace root.

The manual must include separate first-time setup paths for:

- Windows
- Linux/macOS

Each path should include exact launcher commands:

- Windows:
  - `.aib_brain\run.bat`
- Linux/macOS:
  - `sh .aib_brain/run.sh`

### Configuration Coverage

The configuration section should focus on the main user-facing AIB configuration files:

- `.aib_memory/aib-setup.yaml`
- `.aib_memory/instructions.md`

The manual should explain, in beginner-friendly language:

- what each file is for;
- when a new user should edit it;
- what kind of settings or directives belong there;
- what should not be stored there, especially secrets, credentials, tokens, or sensitive information.

Advanced configuration through conventions, prompts, or framework internals is out of scope for the onboarding manual.

### Basic Usage Coverage

The manual should provide step-by-step instructions for a first successful AIB workflow:

1. Open the repository workspace.
2. Confirm `.aib_brain/` and `.aib_memory/` are present.
3. Launch the AIB menu.
4. Write a request into `.aib_memory/input.md`.
5. Run analysis using:
   - `Execute .aib_brain/prompts/aib-analyze.md`
6. Review generated analysis and plan artifacts.
7. Answer any generated Q-blocks in `.aib_memory/input.md`.
8. Re-run analysis if answers were provided.
9. Run implementation using:
   - `Execute .aib_brain/prompts/aib-implement.md`
10. Confirm the request is closed and artifacts are preserved.

The manual should also explain the main prompt invocations:

- `Execute .aib_brain/prompts/aib-analyze.md`
- `Execute .aib_brain/prompts/aib-implement.md`
- `Execute .aib_brain/prompts/aib-refresh-context.md`
- `Execute .aib_brain/prompts/aib-modify.md`
- `Execute .aib_brain/prompts/aib-sync-spec.md`
- `Execute .aib_brain/prompts/aib-input-from-context.md`
- `Execute .aib_brain/prompts/aib-clarify.md`

### Troubleshooting Coverage

Include a general troubleshooting section only.

Do not create a detailed symptom/cause/fix troubleshooting matrix.

The troubleshooting section should provide general guidance such as:

- verify Python is available;
- verify the terminal is opened at the workspace root;
- verify `.aib_brain/` and `.aib_memory/` exist;
- run the launcher again to inspect state-aware menu guidance;
- check `.aib_memory/input.md` for pending questions or active request state;
- check `.aib_memory/context.md` if AIB appears to misunderstand the workspace;
- avoid manually editing tool-managed state unless the manual explicitly says it is safe.

### Best Practices Coverage

Add a best-practices section for new users covering:

- write clear, bounded requests in `.aib_memory/input.md`;
- prefer analysis before implementation for non-trivial changes;
- answer Q-blocks carefully because they influence the plan;
- keep `.aib_memory/instructions.md` concise and stable;
- never store secrets, credentials, tokens, or sensitive information in AIB artifacts;
- refresh context after significant workspace changes;
- review generated plans before implementation;
- keep AIB requests scoped to one coherent unit of work.

### Out of Scope

The manual should not:

- document AIB internals in deep developer detail;
- explain how to modify AIB prompt files or conventions;
- add external dependencies;
- add network-loaded assets;
- convert the guide to Markdown or another file format;
- create new files;
- implement symptom/cause/fix troubleshooting tables.

### Success Criteria

- `.aib_brain/user_guide.html` is rewritten as a self-contained onboarding manual.
- The page uses a linear manual-style layout with a left-pane navigation section.
- The left-pane navigation links jump to the major document sections.
- The manual includes installation instructions based on `versions/aib_brain_vX.Y.Z.zip`.
- The manual includes separate Windows and Linux/macOS setup commands.
- The manual explains `.aib_memory/aib-setup.yaml` and `.aib_memory/instructions.md`.
- The manual includes step-by-step basic usage for a first AIB request.
- The manual includes general troubleshooting guidance only.
- The manual includes beginner-oriented best practices.
- The file remains browser-viewable without network access.
- No additional files are created.
