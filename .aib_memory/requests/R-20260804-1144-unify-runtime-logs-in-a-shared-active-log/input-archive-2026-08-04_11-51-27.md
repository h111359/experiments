## Input

### Goal

Replace separate general and request-scoped runtime logs with one shared active log at `.aib_memory/log.md`. When a request closes, archive the entire shared log in that request’s folder as `log_<request_id>.md`, then leave a new empty `.aib_memory/log.md`.

### Stakeholders and value

- Primary users: AIB users and maintainers.
- Current pain: runtime events are fragmented across general and request-named logs.
- Benefit: one predictable chronological audit stream and consistent closure behavior.
- Priority: normal; implement in the next available iteration.

### Scope

- Make every `log-entry.py` invocation append to `.aib_memory/log.md`, whether or not a request is active.
- Remove the `--general` option and update every repository caller.
- Remove active-request validation from logging.
- During request closure, archive all current `log.md` content, including entries recorded before request creation.
- Name the archived file `log_<request_id>.md`.
- After archival, leave `.aib_memory/log.md` present and empty.
- If `log.md` is absent at closure, create both an empty archived log and an empty root log.
- If the archived log already exists, append the root log to it without replacing existing content, then clear the root log.
- Update conventions, documentation, prompts, tests, and product context affected by the behavior.

### Out of scope

- Migrating, merging, renaming, or deleting existing legacy `log_general.md` and `log_<request_id>.md` files.
- Changing CI-generated release logs under `logs/`.
- Changing the timestamp or entry-line format.
- Introducing network or third-party dependencies.

### Constraints and assumptions

- Logging remains Python-standard-library-only.
- Each entry retains the UTC `YYYYMMDD-HHmmss: <message>` format.
- `log.md` may be created lazily on its first write.
- Existing legacy files remain untouched after upgrade.
- Closure must preserve audit data during retries or partial prior executions.
- All prompt invocations using `--general` must be updated before that option is removed.

### Success criteria

- Logging succeeds in both idle and active-request states.
- Every new entry is appended only to `.aib_memory/log.md` and emitted to stdout.
- `log-entry.py` no longer exposes or accepts `--general`.
- No new general or request-named root log is generated.
- Closing a request archives the complete shared log as `log_<request_id>.md`.
- Closure leaves an existing, zero-length `.aib_memory/log.md`.
- Closing without a root log still creates an empty archived log.
- An existing archived log is preserved and extended rather than overwritten.
- Legacy logs and release logs remain unchanged.
- Relevant automated tests and context validation pass.
