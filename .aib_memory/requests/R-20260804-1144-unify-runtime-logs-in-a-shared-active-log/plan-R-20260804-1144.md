## Goal

Replace the two active runtime-log files (`.aib_memory/log_general.md` and `.aib_memory/log_<request_id>.md`) with a single shared active log at `.aib_memory/log.md` that accepts every `log-entry.py` invocation regardless of workspace state, and rotate that shared stream into `<request-folder>/log_<request_id>.md` when a request is closed so the full chronological audit trail — including pre-request activity — is preserved under the closing request's identifier. Impacted components: `.aib_brain/tools/log-entry.py`, `.aib_brain/tools/move-request-artifacts.py`, `.aib_brain/tools/close-request.py`, five prompt files that still pass `--general`, `.aib_brain/conventions/log-convention.md`, `.aib_brain/README.md`, `.aib_brain/user_guide.html`, `.aib_memory/context.md`, `logs/next_version_changes.md`, and three existing plus one new automated-test file under `tests/`.

## Constraints

- Only the Python 3 standard library may be used; no new external dependencies.
- The UTC entry format `YYYYMMDD-HHmmss: <message>` and the stdout echo behaviour of `log-entry.py` must remain unchanged.
- Legacy `.aib_memory/log_general.md`, root-level `.aib_memory/log_<request_id>.md`, and CI-generated `logs/version_v*.md` files must not be created, moved, deleted, or otherwise modified by the change.
- The archival transaction owned by `move-request-artifacts.py` provides at-least-once delivery; duplicate entries after an ambiguous crash are acceptable.
- Concurrency contract: AIB prompt execution and request closure are single-writer operations; the change does not introduce a cross-process lock.
- Both `.aib_memory/log.md` and `<request-folder>/log_<request_id>.md` must be regular non-symlink files; unexpected path types (directory, symlink, other special file) block the operation without modification.
- The rename-to-staging rollover, conditional-newline separator, binary-mode append, and `fsync`-before-cleanup steps described in the analysis are mandatory for the archival transaction.
- `close-request.py` MUST fail closed on log-archive errors: return a non-zero exit and leave the active request unchanged; existing warn-and-continue behaviour for other artifact moves is preserved.
- `log-entry.py` must reject `--general` via standard `argparse` unrecognized-argument handling; no compatibility shim or deprecation warning is introduced.
- Pre-request-suppression prose in `.aib_brain/prompts/aib-analyze.md` and `.aib_brain/prompts/aib-sync-spec.md` MUST be removed; logging failures during preflight are treated as ordinary tool failures.
- `.aib_memory/log.md` is created lazily on first write or first archival; no initializer, launcher, or migration seeds it.
- `.aib_brain/tools/verify-context.py` and `.aib_brain/tools/verify-input.py` MUST continue to pass after all edits.

### Task 2: Archive and Reset the Shared Log

#### Intent

Move ownership of the shared-log archival transaction to `.aib_brain/tools/move-request-artifacts.py` and enforce the fail-closed policy in `.aib_brain/tools/close-request.py`.

#### Outputs

- Updated `.aib_brain/tools/move-request-artifacts.py`.
- Updated `.aib_brain/tools/close-request.py`.

#### Procedure

In `.aib_brain/tools/move-request-artifacts.py`, replace the existing request-named log move branch with a shared-log archival routine bound to the paths `.aib_memory/log.md` (root), a fixed staging path such as `.aib_memory/log-staging-<request_id>.md`, and `<request-folder>/log_<request_id>.md` (archive). Before touching either the root or archive path, verify each existing path is a regular non-symlink file using `pathlib.Path.is_symlink` and `os.stat` with `stat.S_ISREG`; if either check fails, return a non-zero exit code and leave every file unchanged. When the root log exists as a regular non-symlink file, rename it to the staging path with `os.replace`, then create a new empty `.aib_memory/log.md` immediately; if the root log is absent, ensure the archive path exists (create an empty file if absent) and return success without further work. When a staging snapshot is present (either from this run or a leftover from an aborted prior run), open the destination archive in binary append mode, read the last byte of the archive with a seek-to-end check to detect whether a trailing newline is present, and if the archive is non-empty and its last byte is not `\n` and the staging file is non-empty, write a single `b"\n"` separator to the archive; then stream the staging file into the archive in binary mode using a bounded chunk buffer; call `os.fsync` on the archive's file descriptor before closing it; only after `fsync` succeeds, remove the staging file. Preserve idempotency across the explicit pre-close invocation and the safety-net invocation from `close-request.py`: a missing root plus an existing archive path is a no-op; a leftover staging snapshot is drained on the next call before returning success. Do not modify `.aib_memory/log_general.md` or any pre-existing root-level `log_<request_id>.md` file; the routine touches only the three managed paths named above. Emit a clear non-zero exit status and a human-readable stderr line on any failure.

In `.aib_brain/tools/close-request.py`, treat a log-archive failure from `move-request-artifacts.py` as a hard failure: when the mover reports a log-archive error (distinguished either by its non-zero exit code or by a specific error label), do not reset `input.md` state to idle and do not archive the plan or analysis; propagate the non-zero exit code to the caller. Retain the current warn-and-continue behaviour for non-log artifact-move failures (plan and analysis moves). Ensure the idle-transition write of `input.md` happens only in the log-archive-success branch.

Acceptance: In a scratch workspace with an active request and a non-empty `.aib_memory/log.md`, invoking `move-request-artifacts.py` twice in sequence produces the same final state as invoking it once (idempotent); invoking `close-request.py` after simulating a `move-request-artifacts.py` log-archive failure keeps the request active in `input.md` and returns a non-zero exit code.
