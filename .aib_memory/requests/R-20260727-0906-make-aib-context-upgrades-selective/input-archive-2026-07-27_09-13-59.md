## Input

When upgrade to higher version, the process is always to make context upgrade, despite in some cases no change in the context convention. This unnecessary context semantical upgrades should be avoided as they could cause losing or erroneous modification of the collected information.

### Goal

Make AIB context upgrades selective so higher AIB versions do not semantically migrate or regenerate context artifacts whose conventions have not changed.

### Stakeholders and value

- AIB users retain collected context information without unnecessary rewriting or loss.
- AIB maintainers can independently evolve the main context and registered context extensions.
- Upgrade safety is determined by artifact conventions rather than overall AIB SemVer.

### Required behavior

- Continue the existing `.aib_memory` upgrade process when brain and memory versions differ.
- Treat `.aib_memory/context.md` and each registered context extension as independently versioned artifacts.
- Add YAML frontmatter to each context artifact containing `convention_version: <positive integer>`.
- Declare the expected positive-integer version in each corresponding convention file.
- Increment a convention version whenever that convention file changes.
- Compare every artifact’s applied version with its convention’s expected version during upgrade.
- Preserve compatible artifacts unchanged.
- If `context.md` is incompatible, process it through the existing lossless semantic migration workflow.
- If a registered extension is incompatible, regenerate it through its registered refresh prompt.
- Preserve compatible extensions even when another artifact requires migration or refresh.
- Treat missing or invalid artifact version metadata as incompatible. Existing workspaces therefore undergo one initial migration or refresh when adopting this versioning mechanism.
- When work is required, generate one `input.md` directive listing every affected artifact. One execution of `aib-modify.md` must process the complete list.
- Show the migration-completion gate only when at least one context artifact requires migration or refresh.
- When all context artifacts are compatible, set the upgrade state to compatible and continue without migration instructions or confirmation.

### Scope

- Context and context-extension conventions and validators.
- Upgrade compatibility detection and artifact preservation.
- Context migration and extension-refresh orchestration.
- Migration-completion menu behavior.
- Upgrade tests and user-facing upgrade documentation.
- Product context updates describing selective artifact migration and convention versioning.

### Out of scope

- Changing archive creation or other non-context upgrade behavior.
- Preserving active requests or the previous `input.md`.
- Changing the semantic migration algorithm.
- SemVer rules for the overall AIB release.

### Constraints

- Use Python standard-library functionality only.
- Require no network access.
- Keep prompts model-agnostic.
- Preserve compatible artifacts byte-for-byte.
- Continue using registered refresh prompts for incompatible extensions.

### Acceptance criteria

- An overall AIB version mismatch with matching convention versions preserves `context.md` and every compatible extension byte-for-byte.
- No migration directive or completion gate appears when all context artifacts are compatible.
- A main-context version mismatch migrates only `context.md`.
- An extension version mismatch refreshes only that extension.
- Compatible artifacts remain unchanged when another artifact is processed.
- Missing or invalid YAML version metadata triggers processing of only the affected artifact.
- Generated migration input identifies all affected artifacts and is executable through one `aib-modify.md` run.
- Validators reject missing, invalid, or mismatched convention-version metadata after migration completes.
- Automated tests cover compatible, incompatible, mixed, and metadata-missing upgrades.
- Documentation explains version declarations, increment rules, first-upgrade behavior, and selective processing.
