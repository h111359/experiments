## Goal

Make AIB context upgrades selective by versioning each managed context artifact independently, preserving compatible archived artifacts byte-for-byte, and migrating or refreshing only incompatible or blocked artifacts. This protects AIB users' collected context while updating the context conventions, validators, upgrade lifecycle, bounded prompt orchestration, tests, internal documentation, user guide, and product memory.

## Constraints

- Keep the existing brain/memory SemVer mismatch trigger, archive lifecycle, non-context reseeding behavior, request/input preservation rules, and lossless main-context migration algorithm.
- Use only Python's standard library, require no network access, and keep prompts model-agnostic.
- Declare `convention_version: 1` in YAML frontmatter for both managed conventions and current artifacts; require exact applied/expected equality and permit other unique scalar frontmatter keys.
- Use only the upgraded brain's current managed registry to discover extensions; reconcile archived user flags and override `Update: no` only for required compatibility migration.
- Represent affected and blocked artifacts as ordered Markdown records with fixed fields, and authorize only current-registry paths and prompts in the bounded `aib-modify.md` migration mode.
- Process independent records even when one fails, retain successful outputs, aggregate failures, and keep compatibility pending until all listed validators succeed and the user confirms completion.
- Add dedicated version checks, increasing `verify-context.py` reporting from 12 to 13 checks and `verify-context-data-model.py` reporting from 8 to 9 checks.
- Enforce convention-version increments through normative maintainer rules plus declaration and current-fixture tests; do not add a fingerprint manifest or VCS-aware comparison.
- Do not alter unrelated root README content, overall SemVer rules, archive creation, non-context upgrade behavior, or network/runtime dependencies.

## Success criteria

- Both managed context conventions and both current managed artifacts declare version `1` in YAML frontmatter, and validators accept one positive-integer `convention_version` plus other unique scalar keys while rejecting missing, duplicate, malformed, non-positive, nested, or unequal versions.
- During `initialize.py --upgrade`, every artifact in the upgraded brain's current registry is classified independently, compatible archived files are restored with byte-for-byte equality, and incompatible siblings alone are seeded and scheduled for processing.
- All-compatible upgrades set `memory_version_compatibility` to `compatible`, leave `input.md` seed-equivalent, and bypass the migration-completion screen.
- Main-only, extension-only, mixed, missing/invalid-metadata, missing/unsafe-dependency, and `Update: no` scenarios produce deterministic ordered records and remain `initialized-not-populated` while work is incomplete.
- `aib-modify.md` executes only bounded current-registry migration and refresh prompts, processes all independent records, preserves successful results, aggregates failures, validates affected artifacts, and leaves successful completion for manual confirmation.
- Main-context validation reports 13/13 checks and data-model validation reports 9/9 checks for conforming artifacts, with dedicated and actionable convention-version failures.
- Focused upgrade, menu, validator, prompt-contract, formatting, and guide tests pass, and the full `tests/` suite completes with zero failures.
- `.aib_brain/README.md`, `.aib_brain/user_guide.html`, `.aib_memory/context.md`, and `logs/next_version_changes.md` accurately describe the implemented selective-upgrade behavior.
