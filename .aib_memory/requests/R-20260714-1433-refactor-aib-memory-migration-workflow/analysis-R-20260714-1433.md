# Analysis: R-20260714-1433

## Overview

**Request ID:** R-20260714-1433
**Request Title:** Refactor AIB memory migration workflow

### Background

The current `initialize.py --upgrade` workflow generates a migration-ready `input.md` file that embeds the full migration procedure directly in its `## Input` section (Goal, Sources, Reconstruction Targets, Constraints). While functional, this couples the migration instructions with the input generation step, making the procedure harder to maintain and audit independently. The developer's request is to extract the authoritative migration procedure into a dedicated prompt file (`.aib_brain/prompts/aib-context-migration.md`) so that `input.md` becomes a minimal activation signal rather than a migration specification document. A draft of the new prompt already exists in the repository.

### Scope

- Modify `_generate_migration_input()` in `.aib_brain/tools/initialize.py` so the generated `input.md` no longer embeds the full migration procedure.
- Ensure the generated `input.md` contains only: (1) an instruction to execute `.aib_brain/prompts/aib-context-migration.md`, and (2) the workspace-relative path to the archived legacy `context.md`.
- Improve the existing draft `.aib_brain/prompts/aib-context-migration.md` where beneficial (quality and clarity improvements; preserve intent, structure, and rules).
- Update `tests/test_initialize.py` to reflect the new minimal input.md content.
- Update `context.md` to register the new prompt.

### Out of scope

- Changes to the normal request-analysis workflow.
- Changes to request lifecycle management.
- Changes to `context-convention.md`.
- Changes to `verify-context.py` validation behavior.
- Changes to `memory_version_compatibility` lifecycle logic.
- Changes to `aib-modify.md` (it remains the execution entry point).
- Changes to the context placeholder generation logic (`_generate_context_placeholder()`).

## Input Interpretation

### User Original Inputs

Refactor the AIB memory migration workflow so that migration instructions are no longer embedded directly into the generated migration `input.md` content. Introduce `.aib_brain/prompts/aib-context-migration.md` as the authoritative migration procedure for reconstructing a modern `context.md` from a legacy one. The new prompt becomes the primary migration procedure; `aib-modify.md` continues as execution entry point. The generated `input.md` should contain only an instruction to execute the new prompt and the path to the archived legacy `context.md`. The draft `aib-context-migration.md` should be improved where beneficial without being completely rewritten. The migration completion workflow controlled by `memory_version_compatibility` must remain unchanged. Compatibility with the existing input population pattern in `initialize.py` is required.

### AI Interpretation

The scope of this request is a focused refactoring of the upgrade initialization path: `_generate_migration_input()` in `initialize.py` currently constructs a verbose input body that serves as a self-contained migration specification. The refactoring removes this specification from the generated input and relocates it to a dedicated prompt file. The generated `input.md` transitions from a migration specification document to a minimal activation record that tells `aib-modify.md` which prompt to invoke and where to find the migration source. The draft `aib-context-migration.md` requires targeted improvements to: (a) clarify the source path identification mechanism, (b) fix formatting issues (duplicate heading marker), and (c) optionally add post-migration verification guidance. The `aib-setup.yaml` verification logic currently in the migration body should be removed from the generated input (it was part of the embedded instructions and is now superseded by the prompt).

## Research Results

### Workspace Pattern Scan

**`initialize.py` — `_generate_migration_input()`**
- Lines 215–287 build the full migration input body: Goal section with a reconstruction directive, Sources section with primary and optional source paths, Reconstruction Targets section with step-by-step instructions for `context.md` and `aib-setup.yaml`, and Constraints section with "do not restore requests" rules.
- The `context_source_note` logic (lines 244–254) handles the special case where `context.md` is absent from the archive, generating a different instruction: "Run `aib-refresh-context.md` instead of `aib-modify.md`."
- The function uses `_build_input_seed()` as the base, then appends the migration body to the seed (which ends with `## Input\n\n`).

**`.aib_brain/prompts/aib-context-migration.md`**
- Draft exists. The `## Source` section (lines 22–35) currently says "Identify the legacy context file as per the prompt" — vague; does not specify where the path comes from.
- The `### ### Negative knowledge` heading (line 195) has a duplicate `###` prefix — a typo.
- Trailing whitespace on multiple lines.
- No execution context description; no post-migration verification step.
- The migration rules, semantic invariants, section mapping, and quality checks are well-structured and complete.

**`tests/test_initialize.py`**
- `test_upgrade_creates_migration_input()` (line 195) asserts `"### Goal"` is present in input.md after upgrade. This assertion will fail after the refactoring if the new input body no longer contains `### Goal`.
- `test_upgrade_migration_input_contains_archive_path()` (line 243) asserts `"archives/legacy_"` appears in input.md — this invariant should be preserved in the new minimal format.

**`aib-modify.md`** — reads `input.md ## Input` as implementation directive and executes it. No changes needed. It will read the new minimal instruction and execute `aib-context-migration.md` as directed.

**`context.md`** — The `## Solution` section includes an entry describing `initialize.py --upgrade` behavior. The File Structure section lists prompts but does not include `aib-context-migration.md`. Both need updates.

### Industry Knowledge

**Separation of concerns in automation tooling (principle from 12-Factor App and platform engineering practice):** Configuration generators should produce activation signals, not execution specifications. Embedding procedural logic in generated data creates maintenance coupling (the procedure lives in a code file), auditability gaps (the procedure is not tracked as a first-class artifact), and versioning problems (changes to the procedure must coordinate with the generator). Applicability: directly supports the motivation for this refactoring.

**Prompt-as-executable-spec pattern (LLM tooling community):** Storing agent prompts as discrete versioned files (`*.md` under a `prompts/` directory) is an established pattern in AI-assisted development workflows. It enables independent editing, review, and rollback of the procedure without touching the trigger mechanism. Applicability: the requested `aib-context-migration.md` follows this pattern; the refactoring aligns `initialize.py` with it.

**Minimal activation surface principle (software design):** Runtime-generated files should contain only what varies per invocation (the archive path timestamp, workspace path), not what is static and shared (the migration procedure). Static content belongs in tracked artifacts; dynamic content in generated artifacts. Applicability: the refactoring correctly minimizes the generated input.md to only dynamic content (the archive path) and an activation directive.

### AI Agent Critique

- **`initialize.py` — `_generate_migration_input()`**: The function docstring states "the developer opens this file and runs `aib-modify.md`" which is correct, but the function also embeds `aib-setup.yaml` verification logic (Reconstruction Targets section) that arguably belongs in the prompt. Post-refactoring, this should be cleanly removed.
- **`initialize.py` — `_generate_context_placeholder()`**: The placeholder `context.md` references `aib-modify.md` in its content (lines 197–212): "run aib-modify.md with the migration instructions in input.md." After refactoring, this wording may need updating to reference `aib-context-migration.md` indirectly. However, since the placeholder is temporary and is immediately replaced by the migration run, this is low priority.
- **`aib-context-migration.md` — `## Source` section**: The phrase "Identify the legacy context file as per the prompt" is circular and provides no guidance. Needs a concrete instruction on how to find the path.
- **`aib-context-migration.md` — `### ### Negative knowledge`**: Duplicate heading marker is a typo that may confuse AI agents parsing the document.
- **`aib-context-migration.md` — trailing whitespace**: Multiple lines have trailing spaces (visible in raw view). This is minor but should be cleaned up.
- **`aib-context-migration.md` — no post-migration validation step**: The prompt does not instruct the AI to validate the output against `context-convention.md` using `verify-context.py`. Adding this would close the quality loop.
- **`tests/test_initialize.py` — `test_upgrade_creates_migration_input()`**: Asserts `"### Goal"` in the generated input.md. If the new format does not use a `### Goal` subsection, this test will fail. The test assertion should be updated to assert the new expected content.
- **`context.md` — File Structure section**: `aib-context-migration.md` is not listed under `.aib_brain/prompts/`. It should be added.
- **`context.md` — Solution section**: The statement describing `initialize.py --upgrade` behavior (line 107) references the embedded migration instruction format. It needs updating.

### Edge Cases

- **Archive lacks `context.md`**: The current code generates a special fallback instruction ("Run `aib-refresh-context.md` instead"). With the refactoring, this fallback case must still be handled. Options: preserve the conditional in `initialize.py` (different input.md when absent), or move the fallback logic into `aib-context-migration.md`.
- **Multiple upgrades in same second**: Existing counter-suffix logic handles this; unaffected by this refactoring.
- **`_build_input_seed()` base template compatibility**: The new minimal body must still append cleanly after the `## Input\n\n` section end of the seed template.
- **`aib-modify.md` reading the minimal instruction**: When `aib-modify.md` reads "Execute `.aib_brain/prompts/aib-context-migration.md`", the AI must understand this as a directive to follow that prompt's instructions. The exact phrasing of the activation instruction matters.
- **`aib-context-migration.md` reading the archive path from input.md**: During `aib-modify.md` execution, `input.md` has been read in Step 4 but not yet archived (Step 8). The prompt, executed in Step 7, can still access input.md for the archive path. This is a valid and safe access pattern.

## Proposed Solution

### High-Level Concept

Modify `_generate_migration_input()` in `initialize.py` to produce a minimal activation `input.md` that instructs `aib-modify.md` to execute `.aib_brain/prompts/aib-context-migration.md` with the legacy archive path, and improve the draft `aib-context-migration.md` with a clear source-identification section, a fixed heading typo, and a post-migration verification step.

### Execution Steps

#### Task 1: Improve `aib-context-migration.md`

- `.aib_brain/prompts/aib-context-migration.md`: Update the `## Source` section to instruct the AI to read the migration source path from the current `input.md ## Input` section (provided by `initialize.py --upgrade`).
- `.aib_brain/prompts/aib-context-migration.md`: Fix the `### ### Negative knowledge` duplicate heading to `### Negative knowledge`.
- `.aib_brain/prompts/aib-context-migration.md`: Remove trailing whitespace from all lines.
- `.aib_brain/prompts/aib-context-migration.md`: Add a `## Post-Migration Verification` section instructing the AI to run `python .aib_brain/tools/verify-context.py --workspace .` after producing the migrated `context.md` and to fix any reported issues before completing.

#### Task 2: Modify `_generate_migration_input()` in `initialize.py`

- `.aib_brain/tools/initialize.py`: Replace the body of `_generate_migration_input()` to produce a minimal input body as a single short prose paragraph combining the activation directive to execute `.aib_brain/prompts/aib-context-migration.md` and the workspace-relative path to the archived legacy `context.md`, with no sub-headings under `## Input`.
  - Preserve the existing absent-context conditional: when `context.md` is absent from the archive, generate input.md referencing `aib-refresh-context.md` instead of `aib-context-migration.md`.
  - The new body must use `_build_input_seed()` as the base and append after `## Input\n\n`.

#### Task 3: Update Tests in `test_initialize.py`

- `tests/test_initialize.py`: Update `test_upgrade_creates_migration_input()` to assert the new minimal content (activation directive) rather than `"### Goal"`.
- `tests/test_initialize.py`: Verify that `test_upgrade_migration_input_contains_archive_path()` still passes (archive path format must be preserved in the new minimal body).

#### Task 4: Update `context.md`

- `.aib_memory/context.md`: Add `aib-context-migration.md` to the File Structure section under `.aib_brain/prompts/`.
- `.aib_memory/context.md`: Update the Solution section entry describing `initialize.py --upgrade` behavior to reflect that generated `input.md` now references `aib-context-migration.md` for migration execution rather than embedding migration instructions directly.
- `.aib_memory/context.md`: Add a Solution section entry documenting `aib-context-migration.md` as a dedicated migration prompt for reconstructing `context.md` from a legacy archived version.

### Decision Points

#### Decision Point: DP-01 — Absent-Context Fallback Handling
- Tag: `resolved-by-user`
- Rationale: Developer selected Option A (Q001). The conditional behavior for missing `context.md` in the archive (lines 244–254 of `initialize.py`) must be preserved in `initialize.py`. When `context.md` is absent from the archive, `initialize.py` continues to generate an `input.md` that references `aib-refresh-context.md` rather than `aib-context-migration.md`.
- Resolution: **Option A** — Preserve the conditional in `initialize.py`: when `context.md` is absent from the archive, `initialize.py` still generates an `input.md` that references `aib-refresh-context.md` rather than `aib-context-migration.md`. This preserves the existing branch behavior exactly.

#### Decision Point: DP-02 — Input.md Body Structure
- Tag: `resolved-by-user`
- Rationale: Developer selected Option A (Q002). The new minimal input.md body uses a single short prose paragraph combining the activation directive and archive path, with no sub-headings under `## Input`.
- Resolution: **Option A** — Minimal prose block: a single short paragraph combining the directive and the path, with no sub-headings under `## Input`.

#### Decision Point: DP-03 — Source Path Identification in Prompt
- Tag: `resolved-by-user`
- Rationale: Developer selected Option A (Q003). `aib-context-migration.md` must instruct the AI to read the migration source path from the current `input.md ## Input` section, accessible during `aib-modify.md` Step 7 before archival at Step 8.
- Resolution: **Option A** — Read from `input.md ## Input`: the prompt instructs the AI to read the migration source path from the current `input.md ## Input` section, which is still accessible during `aib-modify.md` Step 7 (before archival in Step 8).

#### Decision Point: DP-04 — Post-Migration Verification Step
- Tag: `resolved-by-user`
