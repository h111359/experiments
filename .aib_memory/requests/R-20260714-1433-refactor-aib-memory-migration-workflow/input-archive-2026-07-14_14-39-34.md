## Input

### Goal

Refactor the AIB memory migration workflow so that migration instructions are no longer embedded directly into the generated migration input.md content.

Introduce a new prompt file:

.aib_brain/prompts/aib-context-migration.md

The new prompt becomes the authoritative migration procedure for reconstructing a modern context.md from a legacy context.md.

### Scope

- Add support for aib-context-migration.md as a dedicated migration prompt.
- Preserve the existing migration workflow initiated by initialize.py --upgrade.
- Preserve the existing use of aib-modify.md as the execution entry point after migration initialization.
- Modify migration input generation so that migration instructions are no longer embedded directly into input.md.
- Generate input.md containing:
  - an instruction to execute .aib_brain/prompts/aib-context-migration.md;
  - the path to the archived legacy context.md that must be used as the migration source.
- Improve the draft aib-context-migration.md prompt where beneficial, while preserving its existing intent, structure, semantic-preservation philosophy, and migration rules.
- Maintain compatibility with the current migration-completion workflow controlled by memory_version_compatibility.
- Use `.aib_brain/prompts/aib-context-migration.md` as the migration prompt for context migration, with the legacy context.md as the only migration source. If seen necessary - make improvements to the draft aib-context-migration.md prompt, but preserve its existing intent, structure, semantic-preservation philosophy, and migration rules.

### Constraints

- The migration prompt must be a new artifact and not a replacement of aib-modify.md. Use `.aib_brain/prompts/aib-context-migration.md` as the migration prompt. aib-modify.md still shall execute the input.md entry.
- Existing upgrade flow behavior must remain unchanged except for relocation of migration instructions into the dedicated prompt.
- The generated migration input.md must continue to follow the existing input population pattern used by initialize.py.
- aib-modify.md remains the execution mechanism used after migration initialization.
- The migration prompt must continue to use the archived legacy context.md as the sole migration source.
- Existing migration semantics, lossless-transformation requirements, and context-convention compliance requirements must be preserved - implied in the migration prompt `.aib_brain/prompts/aib-context-migration.md.
- Improvements to the draft aib-context-migration.md should be evolutionary and quality-focused rather than a complete rewrite.

### Out of Scope

- Changes to normal request-analysis workflow.
- Changes to request lifecycle management.
- Changes to context-convention.md.
- Changes to verify-context.py validation behavior.
- Changes to memory_version_compatibility lifecycle logic.
- Changes unrelated to migration initialization.

### Success Criteria

- A new prompt file .aib_brain/prompts/aib-context-migration.md exists.
- initialize.py --upgrade generates migration input.md without embedding the full migration procedure.
- Generated input.md references execution of aib-context-migration.md.
- Generated input.md contains the path to the archived legacy context.md migration source.
- The migration workflow remains executable through the existing aib-modify.md process.
- Existing migration-completion behavior remains unchanged.
- Semantic migration requirements from the supplied draft are preserved and improved where appropriate.
