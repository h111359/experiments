## Goal

Protect every path under `.aib_brain/` from ordinary AIB workflow writes while preserving installation, upgrade, and explicitly authorized framework-maintenance changes. Consolidate the policy in the coding convention, propagate authorization through analysis and planning, require `.aib_memory/scratch/` for AIB-prescribed in-repository helpers, prevent Python bytecode contamination, validate release archives, and update tests and documentation.

Impacted components are `.aib_brain/conventions/coding-general-convention.md`, all writing prompts under `.aib_brain/prompts/`, `.aib_brain/run.bat`, `.aib_brain/run.sh`, `.aib_brain/tools/menu.py`, `.aib_brain/tools/initialize.py`, `.aib_brain/tools/finalize-input.py`, `scripts/release_bookkeeping.py`, `.aib_memory/context.md`, framework documentation, release notes, and the pytest suite.

## Constraints

- Authorization: This request explicitly authorizes the `.aib_brain/` framework-maintenance changes listed in this plan. Source: original developer input, preserved in `analysis-R-20260819-1437.md ## Overview → ### Authorization`.
- The current request also authorizes the repository-specific `scripts/release_bookkeeping.py` archive-validation change; this does not establish a portable AIB policy for host-project directories.
- Every path under `.aib_brain/` is protected except during installation, upgrade, or an explicitly authorized framework-maintenance request.
- `.aib_brain/` authorization may be a statement semantically equivalent to `This request explicitly authorizes changes under .aib_brain/.` in `input.md ## Input` or the developer chat message; exact wording is not fixed.
- Every `.aib_brain/` instruction that prescribes an in-repository task-specific helper must use `.aib_memory/scratch/`; AIB does not define a destination or authorization model for long-lived host-project tooling.
- Preserve model-agnostic, deterministic, standard-library-only operation with no network access or new runtime dependency.
- Do not modify or depend on the host workspace `.gitignore`, relocate bytecode caches, add filesystem permissions, or add a dedicated write-guard tool.
- Do not remove or investigate pre-existing project-specific helpers, `__pycache__/`, `.pyc`, or `.pytest_cache/` content under `.aib_brain/`; record remaining contamination as a context issue.
- Unauthorized `.aib_brain/` changes halt and report exact paths without automatic revert.
- Do not modify `.aib_memory/instructions.md`; the developer explicitly excluded every change to that file from this request.
- Preserve unrelated user changes in `.aib_brain/prompts/aib-clarify.md` and `.aib_brain/prompts/aib-execute.md`, all unrelated persistent directives, and all unrelated context issues.

## Success criteria

- `.aib_brain/conventions/coding-general-convention.md` contains the canonical `.aib_brain/` write-protection, semantic authorization, scratch-location, bytecode-prevention, and halt/report rules.
- Each of the 12 writing prompts contains the same concise protection block and references `coding-general-convention.md § 12`; `.aib_brain/prompts/aib-context-read.md` remains read-only and exempt.
- Analysis, modify, execute, and implementation workflows enforce and propagate user-sourced semantic `.aib_brain/` authorization.
- Every prompt-prescribed direct AIB Python command uses `python -B` or `python3 -B`.
- Both launchers set `PYTHONDONTWRITEBYTECODE=1`; `.aib_brain/tools/menu.py` invokes child Python tools with `-B` and the bytecode-disabled environment.
- `.aib_brain/tools/initialize.py` seeds `.aib_memory/scratch/`; `.aib_brain/tools/finalize-input.py` preserves `.gitkeep` and removes all other scratch content during archive/reset.
- `scripts/release_bookkeeping.py` refuses archive creation before opening the zip when `.aib_brain/` contains `__pycache__/` or `.pyc`, and reports sorted offending paths.
- New and extended tests cover policy text, prompt coverage, authorization propagation, scratch lifecycle, bytecode prevention, menu child processes, and archive rejection without codifying a generic host-project `scripts/` policy.
- `python -B -m pytest tests/` completes with exit code 0 and all tests passing.
- `.aib_memory/context.md`, `.aib_brain/README.md`, `.aib_brain/user_guide.html`, and `logs/next_version_changes.md` accurately describe the implemented behavior and residual issues.
