## Input

### Goal

Prevent every AIB workflow from modifying any path under `.aib_brain/`, except during installation, upgrade, or an explicitly authorized framework-maintenance request.

This request explicitly authorizes the required `.aib_brain/` framework changes.

### Problem

Project-specific Python helper scripts were created under `.aib_brain/tools/` during implementation, as shown in `.aib_memory/attachments/624418228-59c8a7e5-6e8a-4251-9ab4-62af94f85118.png`. Framework-owned assets must remain isolated from project implementation output.

Existing rules are inconsistent because ordinary implementation currently requires updates to `.aib_brain/README.md` and `.aib_brain/user_guide.html`.

### Stakeholders

- AIB users executing project implementation workflows.
- AIB maintainers performing authorized framework maintenance.
- Repository contributors reviewing framework integrity.

### Scope

- Audit every prompt capable of creating, editing, moving, or deleting files.
- Define the complete canonical protection policy in `.aib_brain/conventions/coding-general-convention.md`.
- Add a concise mandatory prohibition and canonical-convention reference to every applicable writing prompt.
- Require explicit `.aib_brain` authorization in `input.md`, propagated into the analysis and plan.
- Preserve installation, upgrade, and explicitly authorized framework-maintenance workflows.
- Remove ordinary implementation requirements to update `.aib_brain/README.md` and `.aib_brain/user_guide.html`.
- Revise `.aib_memory/instructions.md` to remove the conflicting documentation exceptions.
- Direct task-specific helper scripts to an OS temporary location or existing project-owned directory and require their removal after use.
- Make bytecode prevention self-contained within the distributed `.aib_brain/` package, without modifying or depending on the host repository's `.gitignore`.
- Set `PYTHONDONTWRITEBYTECODE=1` in AIB launchers for the launcher process and inherited child processes.
- Require every prompt-prescribed direct AIB Python command to use Python's `-B` flag.
- Require `menu.py` to preserve the bytecode-disabled environment and invoke Python child tools with `-B`.
- Ensure versioned `.aib_brain/` archives exclude and reject `__pycache__/` directories and `.pyc` files.
- Add automated tests covering every affected workflow, authorization exceptions, detection, and failure behavior.
- Update context, framework documentation, user guide, and release notes for this authorized framework change.

### Protection Policy

- Every path under `.aib_brain/` is protected without implicit documentation, tooling, cache, or generated-artifact exceptions.
- Ordinary project workflows must not create, modify, move, or delete protected content.
- Installation and upgrade workflows may modify `.aib_brain/`.
- Framework-maintenance requests may modify `.aib_brain/` only when `input.md` explicitly authorizes it and the authorization is propagated into the analysis and plan.
- AIB launchers must set `PYTHONDONTWRITEBYTECODE=1` before invoking Python so the setting is inherited by launcher-started child processes.
- Prompt-prescribed direct invocations of scripts under `.aib_brain/tools/` must use `python -B` or `python3 -B`, as appropriate for the platform.
- Python child-tool invocations initiated by `menu.py` must include `-B` and inherit an environment containing `PYTHONDONTWRITEBYTECODE=1`.
- Test caches and all other generated or project-specific artifacts under `.aib_brain/` are prohibited.
- Packaged `.aib_brain/` archives must not contain `__pycache__/` directories or `.pyc` files, and archive validation must fail if either is present.
- Enforcement must use prompt and convention instructions without adding a dedicated guard tool.
- Applicable prompts must inspect for unauthorized protected-path changes.
- On detection, the workflow must halt, report every affected path, and preserve files for user resolution.
- Workflows must not automatically revert files because they may contain pre-existing user changes.

### Existing Files

Do not remove existing helper scripts, caches, or other files as part of this request. This change prevents recurrence only.

### Constraints

- Preserve model-agnostic and dependency-free AIB operation.
- Preserve existing installation and upgrade behavior.
- Preserve explicitly authorized framework-maintenance workflows.
- Do not relocate Python bytecode caches; prevent their creation under `.aib_brain/`.
- Do not modify or depend on the host workspace's `.gitignore` for framework correctness.
- Direct external invocation that bypasses AIB launchers and prescribed commands is outside AIB's execution control, but distributed archives must remain free of bytecode artifacts.
- Avoid duplicated full policy text across prompts; the coding convention remains canonical.
- Keep prompt behavior deterministic.
- Do not use network access or add runtime dependencies.

### Out of Scope

- Removing or investigating existing task-specific scripts or cache directories.
- Automatically reverting unauthorized modifications.
- Adding filesystem permissions or a dedicated write-blocking tool.
- Protecting files outside `.aib_brain/`.
- Changing installation or upgrade semantics beyond documenting their exception.

### Success Criteria

- Every file-writing prompt is audited and covered by the protection policy.
- Every applicable prompt contains a concise prohibition and canonical convention reference.
- Ordinary implementation no longer requires README or user-guide changes inside `.aib_brain/`.
- Explicit authorization is required and propagated before framework-maintenance changes are allowed.
- Project-specific helper scripts are directed outside `.aib_brain/` and removed after use.
- Every prescribed AIB Python command uses `python -B` or `PYTHONDONTWRITEBYTECODE=1`.
- Windows and POSIX AIB launchers set `PYTHONDONTWRITEBYTECODE=1` for their process trees.
- `menu.py` invokes Python child tools with `-B` and propagates the bytecode-disabled environment.
- No prescribed AIB workflow creates `__pycache__` directories or `.pyc` files under `.aib_brain/`.
- No host-workspace `.gitignore` modification is required for bytecode prevention.
- Versioned `.aib_brain/` archives contain no `__pycache__/` directories or `.pyc` files, and validation rejects contaminated archives.
- Unauthorized protected-path changes cause the workflow to halt and list exact paths without reverting them.
- Automated tests cover ordinary, installation, upgrade, authorized-maintenance, unauthorized-change, bytecode-prevention, and generated-artifact scenarios.
- Context, documentation, user guide, and release notes accurately describe the resulting behavior.
- The complete test suite passes.
