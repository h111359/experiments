### Goal

Improve the AIB upgrade workflow to prevent users from assuming that memory migration is complete immediately after `initialize.py --upgrade` finishes.

### Background

Currently, after a memory upgrade the user is returned to the normal menu. This creates the impression that the upgrade process is fully complete, even though the generated migration instructions still need to be executed through `aib-modify.md`.

The upgrade process must become a multi-step workflow with explicit state tracking and recovery after interruption.

### Scope

#### Upgrade Compatibility State Management

Introduce a new field in `.aib_memory/aib-setup.yaml`:

```yaml
memory_version_compatibility:
````

Allowed values:

* compatible
* not-compatible
* initialized-not-populated

State lifecycle:

```text
compatible
    ↓ (framework version != memory_version)
not-compatible
    ↓ (initialize.py --upgrade)
initialized-not-populated
    ↓ (user confirms migration completed)
compatible
```

#### Compatibility Detection

AIB MUST compare:

* Installed framework version
* Memory version in `.aib_memory/aib-setup.yaml`

Compatibility uses strict version equality.

If versions differ:

* workspace automatically transitions to `not-compatible`
* state is persisted in `memory_version_compatibility`
* normal menu access is blocked

#### Upgrade Execution

When the user chooses upgrade:

* `initialize.py --upgrade` executes as normal
* memory version is updated to match the installed framework version
* generated migration instructions are written to `input.md`
* `memory_version_compatibility` is set immediately to `initialized-not-populated`

#### Upgrade Completion Workflow

When `memory_version_compatibility=initialized-not-populated`:

* normal menu must not be displayed
* a dedicated migration-completion screen must be displayed automatically
* workflow must survive application restart
* reopening AIB resumes this state automatically

The migration-completion screen displays:

* explanation that migration instructions in `input.md` must be executed using `.aib_brain/prompts/aib-modify.md`
* option: Confirm Completed
* option: Exit

No other menu options are available.

#### Completion Confirmation

AIB trusts the user.

When the user selects Confirm Completed:

* no verification is performed
* `memory_version_compatibility` becomes `compatible`
* normal menu becomes available

#### Upgrade Request Generation

Upgrade migrations continue to use the standard AIB request workflow.

After initialization:

* `input.md` contains the generated migration instructions
* user executes them using `aib-modify.md`
* no special migration-request mechanism is introduced

### Archive Folder Simplification

Remove usage of:

```text
.aib_memory/archive/
```

Canonical directory must be:

```text
.aib_memory/archives/
```

No backward compatibility is required because there are currently no active users.

Update:

* initialize.py
* upgrade workflows
* documentation
* file structure references

to consistently use `.aib_memory/archives`.
