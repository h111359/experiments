# Plan: R-20260702-0903

## Goal

Replace the `.aib_memory` upgrade workflow in `.aib_brain/tools/initialize.py` with a migration-preparation pattern that archives the full legacy memory state, constructs a minimal conforming memory structure, and injects structured migration instructions into `input.md` for the developer to execute via `aib-modify.md`, eliminating post-upgrade failures caused by incompatible legacy `context.md` structures.

Impacted components: `.aib_brain/tools/initialize.py` (core behavior change), `tests/test_initialize.py` (test updates), `.aib_brain/README.md` (documentation), `.aib_brain/user_guide.html` (user-facing documentation), `.aib_memory/context.md` (two new entries via `edit-context.py`).

## Constraints

- `instructions.md` MUST be copied unchanged from the archive — developer directives must not be lost.
- `context.md` MUST NEVER be restored from archive — always generate a fresh valid placeholder conforming to `context-convention.md`.
- `input.md` MUST NOT be restored from archive — always generate migration-ready content using `_build_input_seed()` as base.
- `requests/` directory MUST remain empty in new active memory after upgrade — legacy requests remain exclusively in the archive.
- `aib-setup.yaml` merge-restore behavior (preserve `default_questions_number`, update `memory_version`) MUST be retained unchanged.
- Archive path MUST use `.aib_memory/archive/legacy_YYYYMMDD-HHMMSS/` (singular `archive/`, `legacy_` prefix); collision counter suffix (`-1`, `-2`, ...) retained for same-second runs.
- `_warn_about_legacy_references()` MUST be removed entirely (function body and call site).
- `_prompt_migrate_requests()` MUST be removed entirely (function body and call site).
- `.aib_brain/` files may be modified per this request's explicit scope (README.md, user_guide.html).
- All changes MUST NOT break existing passing tests not covered by this request's scope.

## Success criteria

- `initialize.py --upgrade` creates `.aib_memory/archive/legacy_YYYYMMDD-HHMMSS/` containing full pre-upgrade `.aib_memory/` content (verified by updated test).
- `context.md` after upgrade begins with `# Product Context` and contains all 5 mandatory sections (verified by `verify-context.py` and new test `test_upgrade_creates_valid_context_placeholder`).
- `input.md` after upgrade passes `verify-input.py` and contains migration instructions with sub-headings `### Goal`, `### Sources`, `### Reconstruction Targets`, `### Constraints` in `## Input` (verified by new test `test_upgrade_creates_migration_input`).
- `requests/` directory in active memory is empty after upgrade (verified by new test `test_upgrade_does_not_restore_requests`).
- `instructions.md` after upgrade matches the archived content (verified by rewritten `test_upgrade_restores_curated_files`).
- `_prompt_migrate_requests()` and `_warn_about_legacy_references()` no longer exist in `initialize.py` (verified by absence in source).
- All tests in `tests/test_initialize.py` pass.
- `python -m pytest tests/` passes with no failures.

### Task 3: Add `_generate_migration_input()` helper to `initialize.py`

#### Intent

Add a new helper function `_generate_migration_input(archive_path: Path, memory_root: Path) -> str` that generates a complete `input.md` string with idle YAML header and structured migration instructions in `## Input`, ready for the developer to open in `aib-modify.md`.

#### Procedure

In `.aib_brain/tools/initialize.py`, add a new function `_generate_migration_input(archive_path: Path, memory_root: Path) -> str` above `_run_upgrade()` or near the other helpers.

Read `default_questions_number` from `.aib_memory/aib-setup.yaml` using `get_setup_option("default_questions_number")`. Use this value as the `minimum_questions` argument to `_build_input_seed()`. Call `_build_input_seed(minimum_questions)` to obtain the seed template string with an idle YAML header.

Compute the workspace-relative path of `archive_path` relative to `memory_root.parent` (the workspace root) and format it with forward slashes (replace `os.sep` with `/`). This produces a path like `.aib_memory/archive/legacy_YYYYMMDD-HHMMSS`.

Check whether `archive_path / "context.md"` exists. If it exists, set a string variable `context_source_note` to: `Primary source: \`<relative_archive_path>/context.md\` — the full legacy context.md archived from the pre-upgrade memory.`  If it does not exist, set `context_source_note` to: `Primary source: ABSENT — \`context.md\` was not found in the legacy archive. Run \`aib-refresh-context.md\` instead of \`aib-modify.md\` to create context.md from workspace inspection.`

Build the migration instructions body as a string containing the following sub-sections under `## Input`:

`### Goal` sub-section text: Reconstruct the workspace's `.aib_memory/context.md` (and optionally other memory files) from the archived legacy `.aib_memory/` content located at `<relative_archive_path>/`. The current `context.md` is a valid placeholder that must be replaced with the full workspace context through semantic reconstruction. Run this as an `aib-modify.md` request.

`### Sources` sub-section text: List the following items:
- `<context_source_note>` (primary source)
- `Optional source: \`<relative_archive_path>/input.md\` — archived legacy input.md; may provide useful background; skip if absent or structurally incompatible.`
- `Optional source: \`<relative_archive_path>/aib-setup.yaml\` — archived legacy setup; reference only for \`default_questions_number\` value.`
- `Conventions to follow: \`.aib_brain/conventions/context-convention.md\`, \`.aib_brain/conventions/input-convention.md\`, \`.aib_brain/conventions/q-block-convention.md\`.`

`### Reconstruction Targets` sub-section text: List the following items:
- `context.md — reconstruct all six sections (Product, Concepts, Requirements, Solution, File Structure, and optionally References) from the archived legacy context.md using semantic interpretation. Conform to context-convention.md.`
- `aib-setup.yaml — already seeded correctly by the upgrade script. Verify that \`memory_version\` matches the current brain version and \`default_questions_number\` matches the archived value. Update only if discrepant.`

`### Constraints` sub-section text: List the following items:
- `Do NOT restore requests from the archive. Legacy requests are at \`<relative_archive_path>/requests/\` for reference only.`
- `Do NOT overwrite \`instructions.md\` — it was copied unchanged from the archive.`
- `If optional source files are absent or structurally incompatible, skip them without failure.`
- `Legacy requests were archived and are not restored. Find them at \`<relative_archive_path>/requests/\` if needed.`

Replace the empty `## Input` body in the seed template string with the migration instructions body built above. Return the resulting string.
