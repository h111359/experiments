## Input

### Goal

Replace the current .aib_memory upgrade approach with a migration-preparation workflow that reliably supports upgrades from older memory versions whose structure differs from the current release.

Challenge is that the context.md file is with changed structure which can not be achieved by simple script. The upgrade process needs to handle the new structure and ensure that all necessary data is migrated correctly. In order to transform the context.md file to the new structure, a prompt should be executed to semantically analyze the existing context.md file and generate a new context.md file that adheres to the updated structure. Currently `.aib_brain\prompts\aib-refresh-context.md` is used for this purpose. 

### Business Need

Users currently encounter upgrade failures when attempting to migrate older .aib_memory versions because the old context.md structure cannot always be transformed deterministically by a script. A semantically-aware migration process is required while still keeping the upgrade experience simple and predictable.

### Scope

- Update the upgrade process for .aib_memory.
- Remove the current upgrade logic that attempts to directly migrate incompatible memory structures.
- Archive the entire legacy .aib_memory into:
  .aib_memory/archive/legacy_TIMESTAMP/
- Preserve archived files unchanged.
- Copy legacy instructions.md into the new .aib_memory unchanged.
- Create a fresh .aib_memory structure matching the current framework version.
- Create an empty requests/ folder in the new structure.
- Discontinue the upgrade question that asks whether archived requests should be restored.
- Never restore archived requests into the new requests/ folder.
- Create a valid empty context.md conforming to current context conventions.
- Generate a migration-ready input.md.
- Populate input.md with detailed migration instructions intended for execution through aib-modify.md.
- Generated migration instructions must:
  - Contain exact relative paths to archived legacy files.
  - Reference all relevant conventions required for migration.
  - Instruct aib-modify.md to semantically analyze archived files.
  - Reconstruct context.md according to the current context structure.
  - Reconstruct input.md according to the current input structure.
  - Reconstruct aib-setup.yaml according to the current memory structure.
- Legacy context.md is the primary migration source.
- Legacy input.md and aib-setup.yaml are optional migration inputs.
- Migration instructions must explicitly state that missing or incompatible legacy input.md or aib-setup.yaml files must not cause migration failure.
- Migration instructions must direct aib-modify.md to use any compatible information available from those files when possible.
- Upgrade completes after preparing the migration workspace.
- Semantic migration itself is executed later by the user through aib-modify.md.
- Update `.aib_brain\README.md` and `.aib_brain\user_guide.html`

### Stakeholders

- AIB Users performing upgrades.
- AIB Maintainers responsible for framework evolution.

### Constraints

- context.md migration cannot rely on deterministic structural mapping.
- Semantic transformation must be delegated to aib-modify.md.
- Upgrade process must preserve auditability by retaining archived files.
- instructions.md must be copied directly and must not be reconstructed.
- Archived legacy content must remain available after migration.
- New memory structure must conform to current framework conventions.
- Existing archive location behavior must remain:
  .aib_memory/archive/legacy_TIMESTAMP/

### Out of Scope

- Automatic execution of aib-modify.md by the upgrade script.
- Deletion of archived legacy files after migration.
- Automatic restoration of archived requests.
- Changes to instructions.md content.

### Success Criteria

- Upgrade completes successfully for legacy memory versions regardless of legacy context structure.
- Upgrade creates a valid current-version .aib_memory structure.
- Archived files remain available in .aib_memory/archive/legacy_TIMESTAMP/.
- instructions.md is preserved unchanged.
- requests/ is empty after upgrade.
- No request-restoration prompt is displayed.
- context.md placeholder is generated successfully.
- input.md contains complete migration instructions ready for execution through aib-modify.md.
- Migration instructions contain exact archival file locations.
- Migration instructions reference required conventions.
- Migration continues even when legacy input.md or aib-setup.yaml are missing or incompatible.
- After user executes aib-modify.md, normal AIB behavior applies and migration instructions are replaced by the reconstructed content.
-  `.aib_brain\README.md` and `.aib_brain\user_guide.html` are updated with information and guidance for the new upgrade process
