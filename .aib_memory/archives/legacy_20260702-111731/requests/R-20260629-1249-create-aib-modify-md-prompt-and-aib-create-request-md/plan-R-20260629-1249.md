## Goal

Create two new AIB prompt files — `aib-create-request.md` and `aib-modify.md` — and update `aib-analyze.md` to delegate its inline auto-request-creation logic to the new standalone prompt. `aib-modify.md` provides a direct-execution path that reads `input.md ## Input` and implements changes immediately without requiring a prior analysis/plan cycle and without closing the active request. `aib-create-request.md` extracts the Appendix A logic from `aib-analyze.md` so it can be reused by both prompts. Update `context.md` and `README.md` to reflect the new prompts.

Impacted components: `.aib_brain/prompts/` (three files), `.aib_memory/context.md`, `.aib_brain/README.md`.

## Constraints

- All new prompt files MUST be created under `.aib_brain/prompts/` following the same structure and execution-model conventions as existing AIB prompts.
- `aib-modify.md` MUST NOT invoke `move-request-artifacts.py` or `close-request.py`.
- `aib-modify.md` MUST NOT modify `.aib_brain/` assets (inherited from `aib-implement.md` safety rule).
- `aib-modify.md` MUST NOT update `context.md` (resolved: developer manages context via separate analysis cycle).
- `aib-modify.md` does NOT include test execution steps (resolved: developer handles validation).
- `aib-modify.md` does NOT support modifier flags (resolved: single-mode prompt).
- `aib-modify.md` skips all input/context verification (no `verify-input.py` / `verify-context.py` calls).
- `aib-modify.md` MUST halt with error when `state == questions_generated`.
- `aib-modify.md` archives `input.md` and resets to seed template via `finalize-input.py` after successful implementation; YAML state left unchanged.
- `aib-create-request.md` MUST halt with error when `state != idle`.
- `aib-modify.md` inherits full coding-convention enforcement from `aib-implement.md` (same extension-to-convention mapping table).
- New prompts MUST use `log-entry.py --general` for any log call made before an active `request_id` is confirmed.
- `edit-context.py` supports only `Product`, `Concepts`, `Requirements`, `Solution` areas; the `File Structure` section must be edited directly.
- All new file content must be model-agnostic (no vendor-specific instructions).

## Success criteria

- `.aib_brain/prompts/aib-create-request.md` exists and contains: non-idle state guard (halt with error identifying existing `request_id`); derive-title logic; `create-request.py` invocation; `input-header.py` read to confirm new `request_id`; `--general` log calls before request resolution.
- `.aib_brain/prompts/aib-modify.md` exists and contains: `instructions.md` read; `input-header.py` state check; `questions_generated` halt guard; idle-state branch executing `aib-create-request.md`; empty-input halt guard; `context.md` read; coding-convention enforcement matching `aib-implement.md`; implementation step; `finalize-input.py` invocation; commit step; completion confirmation.
- `.aib_brain/prompts/aib-analyze.md` Appendix A procedural steps (A.1–A.4) are replaced with a single delegation instruction to execute `aib-create-request.md`; the Appendix A heading and trigger description are retained.
- `.aib_memory/context.md` `## Solution` contains two new statements for `aib-modify.md` and `aib-create-request.md`; `## File Structure` `prompts/` line lists all five prompts.
- `.aib_brain/README.md` documents both new prompts in the prompts section.
- `python .aib_brain/tools/verify-context.py --workspace .` exits with code 0 after context.md edits.

## Plan

### Task 1: Create aib-create-request.md

#### Intent

Create `.aib_brain/prompts/aib-create-request.md` as a standalone prompt encapsulating the auto-request-creation logic formerly embedded as Appendix A in `aib-analyze.md`.

#### Procedure

Create `.aib_brain/prompts/aib-create-request.md` with the following execution sequence:

Step 1 — Log start using `--general` flag (suppress error on pre-creation call):
Run `python .aib_brain/tools/log-entry.py --workspace . --general --message "aib-create-request: started"`.

Step 2 — State guard: Run `python .aib_brain/tools/input-header.py --workspace . --operation read` and parse `request_id` and `state`. If `state != idle`, halt immediately with the literal error: `ERROR: Active request <request_id> already exists. aib-create-request.md must only be called when state is idle.`

Step 3 — Check input: Read `.aib_memory/input.md` `## Input` section. If the section is absent or contains only whitespace, halt with the literal error: `ERROR: No active request and input.md is empty. Add content to ## Input before running analysis.`

Step 4 — Derive title: Extract the first meaningful sentence or noun phrase from `## Input`, truncated to ≤ 60 characters, as the request title.

Step 5 — Create request: Invoke `python .aib_brain/tools/create-request.py --workspace . --title "<derived-title>"`.

Step 6 — Resolve new request_id: Run `python .aib_brain/tools/input-header.py --workspace . --operation read` and capture the newly created `request_id` from the output.

Step 7 — Log completion using `--general` flag: Run `python .aib_brain/tools/log-entry.py --workspace . --general --message "aib-create-request: complete <request_id>"`.

Step 8 — Output the resolved `request_id` to the conversation.

### Task 2: Create aib-modify.md

#### Intent

Create `.aib_brain/prompts/aib-modify.md` as a direct-execution prompt that reads `input.md ## Input` and implements it immediately using `context.md` and `instructions.md` as guides, without closing the request.

#### Procedure

Create `.aib_brain/prompts/aib-modify.md` with the following execution sequence:

Step 1 — Read `instructions.md`: Read `.aib_memory/instructions.md`. If present and non-empty, treat its content as persistent workspace-level instructions to be observed throughout the entire execution. Log: `python .aib_brain/tools/log-entry.py --workspace . --general --message "aib-modify: Step 1 Read instructions"`.

Step 2 — State check: Run `python .aib_brain/tools/input-header.py --workspace . --operation read` and parse `state`, `request_id`. Apply the following branch logic:
- If `state == questions_generated`: halt immediately with the literal error: `ERROR: Active request <request_id> has unanswered Q-blocks (state: questions_generated). Answer all questions or reset state before running aib-modify.md.`
- If `state == idle`: execute `.aib_brain/prompts/aib-create-request.md`; after it completes, re-run `input-header.py` to resolve the new `request_id` and continue.
- If `state == analysis_ready`: continue.

Step 3 — Log preflight complete: `python .aib_brain/tools/log-entry.py --workspace . --message "aib-modify: preflight complete <request_id>"`.

Step 4 — Read input: Read `.aib_memory/input.md` `## Input` section. If the section is absent or contains only whitespace, halt with: `ERROR: input.md ## Input is empty. Add implementation instructions before running aib-modify.md.`

Step 5 — Read context: Read `.aib_memory/context.md` for product-context awareness. Do NOT update context.md during this execution.

Step 6 — Read coding conventions: Unconditionally read `.aib_brain/conventions/coding-general-convention.md`. Additionally read the language-specific convention file that corresponds to the file extensions being created or edited, using the same extension-to-convention mapping table as `aib-implement.md`.

Step 7 — Implement: Apply the implementation directive from `input.md ## Input`, observing `instructions.md` directives and the loaded coding conventions. Do NOT modify any file under `.aib_brain/`. Do NOT update `context.md`. After completing, log: `python .aib_brain/tools/log-entry.py --workspace . --message "aib-modify: implementation complete"`.

Step 8 — Archive input: Invoke `python .aib_brain/tools/finalize-input.py --workspace . --request-id <request_id>` to archive `input.md` content and reset to seed template. Leave YAML state unchanged. Log: `python .aib_brain/tools/log-entry.py --workspace . --message "aib-modify: input archived"`.

Step 9 — Commit: Follow the `instructions.md` commit directive: create a git commit with a descriptive message referencing the `request_id` and summarising the implemented changes. Message format: `Implementation for request <request_id>: <brief description>`.

Step 10 — Completion confirmation: Output the literal text `--- I am done with the modification of <request_id> ---` as the very last message. Do not add any text after this line.
