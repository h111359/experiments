## Goal

Refactor the AIB context system from a 22-area classified-statement model to a 6-section model (Product, Concepts, Requirements, Solution, File Structure, References). This requires rewriting the convention file that defines the format, rewriting the verification tool that enforces it, updating the editing tool that performs CRUD on it, rewriting the synthesis prompt that generates it, migrating the live context.md to the new structure, updating the analysis and implementation prompts that reference section names, and updating all automated tests that assert on the old format.

Impacted components: `.aib_brain/conventions/context-convention.md`, `.aib_brain/tools/verify-context.py`, `.aib_brain/tools/edit-context.py`, `.aib_brain/prompts/aib-refresh-context.md`, `.aib_brain/prompts/aib-analyze.md`, `.aib_brain/prompts/aib-implement.md`, `.aib_memory/context.md`, `tests/test_verify_context.py`, `tests/test_context_formatting_rules.py`.

## Constraints

- Implementation runs on Python 3 standard library only; no new dependencies may be introduced.
- Changes must not break any test that is not asserting on the old 22-area format.
- edit-context.py `--type` argument applies only to the Requirements section; Product, Concepts, and Solution do not use type letters.
- context.md migration is performed by the implement agent reading the current content and manually rewriting it section by section using the mapping provided in the analysis; aib-refresh-context.md is not invoked during migration.
- verify-context.py must be updated before context.md migration so that validation can be run against the migrated file.
- edit-context.py must be updated before the context update task runs so that new section names are accepted.
- `.aib_brain/` files may be modified by this request (per the context-convention.md and instructions.md exception for framework maintenance requests).

## Success criteria

- `python .aib_brain/tools/verify-context.py --workspace .` exits with code 0 against the migrated `.aib_memory/context.md`.
- All automated tests pass when run with `python -m pytest tests/`.
- `aib-refresh-context.md` Phase 4 generates output matching the 6-section structure defined in the updated `context-convention.md`.
- `edit-context.py --operation insert --area Product` (and Concepts, Requirements, Solution) succeed without "Invalid area name" errors.
- `edit-context.py --operation insert --area Requirements --type MUST` succeeds.
- `context-convention.md` contains exactly the 6 valid section names and no reference to the old 22-area list.
- `tests/test_context_formatting_rules.py` and `tests/test_verify_context.py` all pass without modification after the implementation run completes.

## Plan

### Task 1: Rewrite context-convention.md

#### Intent

Replace the existing context-convention.md with a new version defining the 6-section structure, per-section statement formats, and updated quality gates so that all downstream tools derive their behavior from the new authority.

#### Procedure

Open `.aib_brain/conventions/context-convention.md` for full replacement.

Replace the entire file content with a new convention document containing the following structure and rules:

- Title: `# Convention: context-convention.md`

- **Valid sections (normative):** List exactly 6 valid H2 section names: `Product`, `Concepts`, `Requirements`, `Solution`, `File Structure`, `References`. No other H2 headings are valid in context.md.

- **Statement format rules (normative):**
  - `## Product`, `## Concepts`, `## Solution`: each statement is a bullet line matching `- <text>` (plain text, no type letter, no modality prefix).
  - `## Requirements`: each statement is a bullet line matching `- [MUST|MUST NOT|OPTIONAL]: <text>`. Any Requirements bullet not using one of these three modality prefixes is a format violation.
  - `## File Structure`: content is a human-readable indented directory tree; bullet-statement format is NOT enforced in this section.
  - `## References`: each entry is a `###` sub-heading followed by a `Location:` line and a `Summary:` line. Bullet-statement format is NOT enforced in this section.

- **Mandatory sections (normative):** `## Product` MUST be present and non-empty. `## File Structure` MUST be present. `## References` is optional; if absent, the file is still valid. `## Concepts`, `## Requirements`, `## Solution` are required to be present.

- **Document title (normative):** First line of context.md MUST be `# Product Context`.

- **Quality gates (normative):** Define the following checks that verify-context.py MUST implement:
  1. Document starts with `# Product Context`.
  2. All H2 headings are one of the 6 valid section names.
  3. `## Product` section is present and non-empty.
  4. `## Requirements` section is present.
  5. `## Solution` section is present.
  6. `## File Structure` section is present.
  7. Every statement in `## Product`, `## Concepts`, `## Solution` matches `- <text>` (no type-letter prefix).
  8. Every statement in `## Requirements` matches `- [MUST|MUST NOT|OPTIONAL]: <text>`.
  9. `## References` entries, if any, each have a `###` sub-heading followed by `Location:` and `Summary:` lines.
  10. No HTML tags, no Markdown table rows, no bare URLs in any statement line.

- Remove all references to the old 22-area list, the 9-type-letter system, and the `## 1. Product Identity` / `## 2. Statements` / `## 3. Workspace File Inventory` headings.

Save the file.

### Task 2: Rewrite verify-context.py

#### Intent

Replace the 22-area VALID_AREAS set and all 10 check functions in `.aib_brain/tools/verify-context.py` with new logic validating the 6-section structure defined in the updated context-convention.md.

#### Procedure

Open `.aib_brain/tools/verify-context.py` for editing.

Replace the `VALID_AREAS` set (currently containing 22 items) with a new set containing exactly 6 strings: `"Product"`, `"Concepts"`, `"Requirements"`, `"Solution"`, `"File Structure"`, `"References"`.

Remove the `VALID_TYPES` set and the `STATEMENT_PATTERN` regex (which matches `- TYPE: text`).

Add a new regex `PLAIN_STATEMENT_PATTERN` matching `^- .+$` for use in Product, Concepts, and Solution checks.

Add a new regex `MODALITY_STATEMENT_PATTERN` matching `^- (MUST|MUST NOT|OPTIONAL): .+$` for use in Requirements checks.

Replace all 10 existing check functions with exactly 10 new check functions implementing the quality gates defined in context-convention.md Task 1:

- `check_document_title`: passes when first non-empty line of context.md is `# Product Context`.
- `check_all_h2_headings_valid`: passes when every H2 heading in the document is one of the 6 valid section names.
- `check_product_section_present_and_non_empty`: passes when `## Product` exists and has at least one non-blank line after the heading.
- `check_requirements_section_present`: passes when `## Requirements` heading is present.
- `check_solution_section_present`: passes when `## Solution` heading is present.
- `check_file_structure_section_present`: passes when `## File Structure` heading is present.
- `check_product_concepts_solution_format`: for every bullet line in `## Product`, `## Concepts`, and `## Solution`, verify it matches `PLAIN_STATEMENT_PATTERN` and does NOT contain a type-letter prefix (i.e., does NOT match `^- [A-Z]: ` or `^- (MUST|MUST NOT|OPTIONAL): `).
- `check_requirements_format`: for every bullet line in `## Requirements`, verify it matches `MODALITY_STATEMENT_PATTERN`. A line starting with `- ` that does NOT match the modality prefix is a format violation.
- `check_references_format`: if `## References` is present, verify that each `###` sub-heading is followed within 5 lines by a line containing `Location:` and a line containing `Summary:`. If `## References` is absent, this check passes automatically.
- `check_no_html_tables_urls`: passes when no statement line contains an HTML tag (matched by `<[a-zA-Z/][^>]*>`), a Markdown table row (line starting with `|`), or a bare URL (matched by `https?://`).

Update the `_get_area_sections` helper to skip `File Structure` and `References` when collecting sections for the statement format checks (since those sections use non-bullet formats).

Update the `main` function's `CHECKS` list to reference the 10 new check functions in the order above.

Update the results summary line to read `Results: 10/10 checks passed.` (or the appropriate N/10 count) by keeping the same existing loop that counts passing checks.

Remove the `_parse_args`, `main` function output format changes — keep the existing `--workspace` argument and exit-code behavior unchanged.

Save the file.
