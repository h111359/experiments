## Input

Goal 1: In input.md file organize the rows in two groups - one group for state which is managed by the prompts and tools, and another - which the use can modify. For example minimum_questions, input_verification_enabled and context_verification_enabled are options, which the user can change. On the other hand request_id, title, state, input_verification_result, context_verification_result are not supposed to be modified by the user and should be grouped separately.

Restructure the frontmatter of input.md.
   Currently, we have everything as a flat structure. Let's group properties into 2 groups:
   State:
   - request_id
   - title
   - state (rename from status)
   - input_verification_result
   - context_verification_result
   Options:
   - minimum_questions
   - input_verification_enabled
   - context_verification_enabled
   State properties are meant to be updated only by prompts / tools, Options are meant to be configured by the user

Goal 2: Create a request specific log, which to be populated while executing the prompts `.aib_brain\prompts\aib-analyze.md`, `.aib_brain\prompts\aib-implement.md` and `.aib_brain\prompts\aib-refresh-context.md`. The log entries should be added in a new file .aib_memory/log_<request_id>.md. The prompts should not edit the log directly but for the purpose of adding record create a python script in .aib_brain/tools for creation of the log file if not existing and adding log entries. Create .aib_brain/conventions/log-convention.md. The tool should add rows in the log in format:
<timestamp in format YYYYMMDD-HHmmss>: log message
The tool should be invoked by providing only the log message. The tool should read from input.md the request id and should form the log file name based on it. The tool should return error in case there is no active request (no request id is detected)
The log tool should use the UTC time

We need a way to log request-specific messages to standard output and to `.aib_memory/log_<request_id>.md` file. We need to create a simple python tool to do it, and establish a new convention for it. 
   The tool should only accept the message, while finding the request_id automatically from the input.md file. If request_id is not specified - error out. The format should be: `YYYYMMDD-HHmmss: log message`. Date and time should be in UTC. 
   All prompts need to be instructed to log their actions (aib-analyze.md, aib-implement.md, aib-refresh-context.md)

Goal 3: Add a modification option to `.aib_brain\prompts\aib-analyze.md` prompt. The option should be added like terminal commands options:
`Execute .aib_brain/prompts/aib-analyze.md --plan-only`
The prompt should be instructed to read the whole entry from the user and if meet `--plan-only` option in the chat entry to generate the plan without generating the analysis file and without questions to the user (take recommended answers in case of decisions needed)

We need to add an option to aib-analyze.md to only generate plan if explicitly specified. If the user chat message contains `--plan-only`, the prompt should skip generation of analysis file, skip generating clarifying questions, and jump straight to generating plan, generating recommended answers/assumptions as well in the plan file.

Goal 4: Add a modification option to `.aib_brain\prompts\aib-implement.md` prompt. The option should be added like terminal commands options:
`Execute .aib_brain/prompts/aib-implement.md --exec-input`
The prompt should be instructed to read the whole entry from the user and if meet `--exec-input` option in the chat to treat the Input part of input.md file as the only instruction that should be implemented and not searching for or reading the plan file. 

We need to add an option to aib-implement.md to execute entirely based on the input.md file. If the user chat message contains `--exec-input`, the prompt should not look for or read the plan file, and execute straight off the `## Input` block in the input.md file.
