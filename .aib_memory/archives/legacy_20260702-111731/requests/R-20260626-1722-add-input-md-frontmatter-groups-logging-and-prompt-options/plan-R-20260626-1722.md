## Goal

Restructure `.aib_memory/input.md` YAML frontmatter into two clearly named nested groups (tool-managed state and user-configurable options), introduce a per-request audit log tool and convention, and add `--plan-only` and `--exec-input` runtime modifier flags to `aib-analyze.md` and `aib-implement.md` respectively. Impacted components: `.aib_brain/tools/common.py`, `.aib_brain/tools/verify-input.py`, `.aib_brain/tools/input-header.py`, `.aib_brain/tools/finalize-input.py`, `.aib_brain/tools/initialize.py`, `.aib_brain/tools/move-request-artifacts.py`, `.aib_brain/prompts/aib-analyze.md`, `.aib_brain/prompts/aib-implement.md`, `.aib_brain/prompts/aib-refresh-context.md`, `.aib_brain/conventions/input-convention.md`, `.aib_memory/input.md`, `tests/` test suite, and new files `.aib_brain/tools/log-entry.py` and `.aib_brain/conventions/log-convention.md`.

## Constraints

- Python standard library only; no external package dependencies.
- All tool scripts must remain compatible with Python 3.9+.
- The workflow state sub-field inside the `state:` group is named `status:` (not `state:`) to resolve the `state.state` nesting collision; allowed values remain `idle|analysis_ready|questions_generated`.
- `parse_input_header()` raises `ValueError` if the old flat format is detected; no auto-migration. Existing workspaces must be re-initialized.
- The seed template is centralized in `common.py` as `_INPUT_SEED_TEMPLATE`; both `finalize-input.py` and `initialize.py` import it.
- Log files use `log_{request_id}.md` naming (underscore) and are moved to the request subfolder on close alongside plan and analysis.
- `log-entry.py` supports `--general` flag for writing to `.aib_memory/log_general.md` when no active request is available.
- All prompts log at the start and completion of each numbered execution step.
- `aib-refresh-context.md` always uses `--general` flag for all log-entry.py invocations.
- `aib-implement.md` in `--exec-input` mode still reads `context.md`; only the plan file is skipped.
- `aib-analyze.md` in `--plan-only` mode reads existing `analysis-<request_id>.md` if present for plan source.
- `log-convention.md` specifies format and naming only; no mandatory event enumeration.
- `.aib_brain/` assets may not be modified during implementation per workspace safety rules; this constraint is suspended for this request, which explicitly targets `.aib_brain/` assets.
- The `## Options` body section of `input.md` (containing the human-readable `Minimum questions:` label) is distinct from the `options:` YAML frontmatter block and is NOT restructured by this request.
- All existing tests must pass after changes. New tests must be added for log-entry.py.

## Success criteria

- `python .aib_brain/tools/verify-input.py --workspace .` exits with code 0 on an input.md file using the new nested YAML structure (with `state.status` sub-field).
- `python .aib_brain/tools/input-header.py --workspace . --operation read` outputs all fields correctly from the new nested structure.
- `python .aib_brain/tools/log-entry.py --workspace . --message "test"` creates `.aib_memory/log_<request_id>.md` with a correctly formatted UTC entry and prints the same entry to stdout.
- `python .aib_brain/tools/log-entry.py --workspace .` (normal mode with idle state) exits with code 1 and an informative error.
- `python .aib_brain/tools/log-entry.py --workspace . --message "test" --general` creates `.aib_memory/log_general.md` with a correctly formatted UTC entry regardless of active request state.
- `python -m pytest tests/` passes with all tests including new `tests/test_log_entry.py`.
- `aib-analyze.md` executed with `--plan-only` in the chat message produces a `plan-<request_id>.md` without creating or modifying `analysis-<request_id>.md` and without writing `## Questions` to input.md.
- `aib-implement.md` executed with `--exec-input` in the chat message executes based on `## Input` content without reading any plan file while still reading `context.md`.

### Task 8: Create log-entry.py tool

#### Intent

Create the new `.aib_brain/tools/log-entry.py` script that appends UTC-timestamped log entries to `.aib_memory/log_<request_id>.md` (normal mode) or `.aib_memory/log_general.md` (general mode) and prints to stdout.

#### Procedure

Read `.aib_brain/conventions/coding-python-convention.md` before writing Python code.

Create `.aib_brain/tools/log-entry.py` with the following behavior:

- Accepts `--workspace` argument (default `"."`).
- Accepts `--message` argument (required) as the log message string.
- Accepts optional `--general` flag (store_true) for generic non-request logging mode.
- Normal mode (no `--general` flag): reads input.md via `parse_input_header` imported from `common`; if `status` field indicates idle state, prints `ERROR: No active request found. Cannot write log entry.` to stderr and exits with code 1; constructs log file path as `<workspace>/.aib_memory/log_<request_id>.md`.
- General mode (`--general` flag present): bypasses active-request check entirely; constructs log file path as `<workspace>/.aib_memory/log_general.md`.
- In both modes: gets current UTC datetime using `datetime.now(timezone.utc)`; formats timestamp as `YYYYMMDD-HHmmss` (strftime `%Y%m%d-%H%M%S`); constructs entry string as `{timestamp}: {message}\n`; opens log file in append mode (`"a"`, encoding `"utf-8"`) and writes the entry (creates file if absent); prints the same entry string (without trailing newline) to stdout; exits with code 0 on success.
