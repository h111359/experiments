## Goal

Replace the empty semver marker file convention in `.aib_memory/` with a human-editable YAML setup file named `aib-setup.yaml` containing flat top-level keys `memory_version` and `default_questions_number`. Add a new `read-setup.py` tool so prompts retrieve individual setup values without reading the file directly. Update `common.py`, `initialize.py`, and `menu.py` to use the new file; update tests; update `context.md` and `README.md`.

Impacted components: `.aib_brain/tools/common.py`, `.aib_brain/tools/initialize.py`, `.aib_brain/tools/menu.py`, `.aib_brain/tools/read-setup.py` (new), `tests/test_initialize.py`, `tests/test_menu.py`, `tests/test_read_setup.py` (new), `.aib_memory/context.md`, `.aib_brain/README.md`.

## Constraints

- The brain's semver marker file (`.aib_brain/vX.Y.Z`) is unchanged; only `.aib_memory/` versioning changes.
- No changes to prompt files, `edit-context.py`, `create-request.py`, `close-request.py`, `log-entry.py`, `move-request-artifacts.py`, `verify-input.py`, or `verify-context.py`.
- `aib-setup.yaml` uses flat top-level YAML keys (no nested mapping).
- `read-setup.py` prints bare value to stdout; exits with code 1 and prints to stderr when the requested key is absent; no schema validation.
- `initialize.py` generates `aib-setup.yaml` inline with hardcoded defaults (no template file in `.aib_brain/`).
- On `--upgrade`, existing archived `aib-setup.yaml` is restored to fresh memory then `memory_version` is overwritten with the current brain version; if no archive exists, generate fresh from inline defaults.
- `finalize-input.py` behavior is unchanged: it preserves the existing `minimum_questions` from the current header on reset.
- `_INPUT_SEED_TEMPLATE` in `common.py` keeps hardcoded `minimum_questions: 5` as fallback for legacy workspaces where `aib-setup.yaml` is absent.
- Python 3 standard library only; no third-party packages.
- `edit-context.py` supports only Product, Concepts, Requirements, Solution areas; File Structure section must be edited directly.

## Success criteria

- `.aib_memory/aib-setup.yaml` is created by `initialize.py` with keys `memory_version` (set to current brain version) and `default_questions_number` (set to 5).
- No `v*.*.*` empty file is created in `.aib_memory/` by `initialize.py`.
- `menu.py check_version_compatibility()` reads memory version from `aib-setup.yaml` instead of scanning for `v*.*.*`.
- `read-setup.py --workspace . --option memory_version` prints the bare value (e.g., `v1.5.0`) and exits with code 0.
- `read-setup.py --workspace . --option nonexistent` exits with code 1 and prints an error to stderr.
- `initialize.py --upgrade` restores `aib-setup.yaml` from archive (if present) and then updates `memory_version`; if archive absent, generates fresh defaults.
- `tests/test_initialize.py` `TestSemverSeeding` class tests pass with `aib-setup.yaml` assertions (not `v1.2.8` file assertions).
- `tests/test_read_setup.py` covers bare-value output, missing key (code 1), missing file, and corrupt YAML.
- `python -m pytest tests/` exits with code 0.
- `python .aib_brain/tools/verify-context.py --workspace .` exits with code 0 after context.md edits.

### Task 2: Replace `_seed_semver` with `_seed_setup` in `initialize.py`

#### Intent

Replace the `_seed_semver()` function in `.aib_brain/tools/initialize.py` with a `_seed_setup()` function that creates `aib-setup.yaml` instead of an empty `vX.Y.Z` file; update `_run_upgrade()` to implement the merge-restore strategy; update `_seed_memory()` to seed `minimum_questions` from the setup file.

#### Procedure

Step 1 — In `.aib_brain/tools/initialize.py`, rename and rewrite `_seed_semver(brain_dir, memory_root, force)` to `_seed_setup(brain_dir, memory_root, force)`. The new function must: determine the brain's semver by calling `get_semver(brain_dir)`; write `aib-setup.yaml` to `memory_root` with the following content (using the brain version in `memory_version`):
```
memory_version: <brain_semver>
default_questions_number: 5
```
If `aib-setup.yaml` already exists and `force` is False, skip writing (idempotency). Remove any stale `v*.*.*` empty files from `memory_root` during this step (to clean up legacy workspaces).

Step 2 — In `.aib_brain/tools/initialize.py`, update `_run_upgrade()` to call `_seed_setup` instead of `_seed_semver`. Implement the merge-restore strategy: after archiving the old memory, check whether the archived memory directory contains `aib-setup.yaml`; if it does, copy it to the fresh `memory_root` first, then overwrite only the `memory_version` key in the copied file with the current brain version; if no archived `aib-setup.yaml` exists, call `_seed_setup()` normally to generate fresh defaults.

Step 3 — In `.aib_brain/tools/initialize.py`, update `_seed_memory()` to read `default_questions_number` from the newly created `aib-setup.yaml` (call `get_setup_option(memory_root, "default_questions_number")`). If the value is found and is a valid integer, use it as `minimum_questions` when rendering `_INPUT_SEED_TEMPLATE` for `input.md`. If absent or invalid, fall back to the hardcoded value of 5 in `_INPUT_SEED_TEMPLATE`.

Step 4 — Remove any remaining calls to `_seed_semver` in `initialize.py`.

### Task 4: Create `read-setup.py`

#### Intent

Create `.aib_brain/tools/read-setup.py` as a new standalone tool that reads a single named option from `.aib_memory/aib-setup.yaml` and prints its bare value to stdout.

#### Procedure

Step 1 — Create `.aib_brain/tools/read-setup.py`. The script must accept the following arguments: `--workspace <path>` (workspace root; default `.`) and `--option <key>` (name of the option to retrieve; required).

Step 2 — Logic: construct the path `{workspace}/.aib_memory/aib-setup.yaml`. If the file does not exist, print an error message to stderr (`ERROR: aib-setup.yaml not found at <path>`) and exit with code 1.

Step 3 — Parse `aib-setup.yaml` using the same YAML loading approach used in `get_setup_option()` in `common.py`. If parsing fails (invalid YAML), print an error to stderr and exit with code 1.

Step 4 — Look up the requested option key in the parsed content. If found, print the bare value (converted to string) to stdout with a trailing newline and exit with code 0. If the key is not found, print `ERROR: option '<key>' not found in aib-setup.yaml` to stderr and exit with code 1.

Step 5 — No schema validation is performed; any top-level key present in the YAML is accepted.
