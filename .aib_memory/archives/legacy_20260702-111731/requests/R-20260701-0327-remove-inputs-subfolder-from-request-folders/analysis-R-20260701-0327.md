# Analysis: R-20260701-0327

## Overview

- **Request ID:** R-20260701-0327
- **Request title:** Remove inputs/ subfolder from request folders

### Background

`finalize-input.py` currently creates a `<request-folder>/inputs/` subdirectory to stage two artifact types: the archived `input.md` snapshot (`input-archive-TIMESTAMP.md`) and any files moved from `.aib_memory/attachments/`. This extra indirection adds a layer of directory nesting that does not serve a clear organisational purpose — both artifact types are already scoped to the request folder by name pattern, and the `inputs/` subdirectory is never listed in file-structure documentation as a navigable layer. The developer requests that both artifact types be placed directly at the request folder root, removing the intermediate `inputs/` directory entirely.

### Scope

- `.aib_brain/tools/finalize-input.py` — remove the `inputs_dir` variable and redirect all file operations to `request_folder` directly.
- `tests/test_finalize_input.py` — update all path assertions to reference the request folder root.
- `.aib_brain/prompts/aib-analyze.md` — update GC-01 guard clause and S07 step descriptions.
- `.aib_brain/prompts/aib-implement.md` — update the MUST NOT guard clause for archive files.
- `.aib_memory/context.md` — update the Solution section statement describing archive placement.
- `.aib_brain/README.md` — update the artifact table row for input archives.
- `.aib_brain/user_guide.html` — update two occurrences referencing the `<request-folder>/inputs/` path.

### Out of scope

- Migration of existing closed request folders — the developer explicitly excludes this.
- Changes to the `create-request.py` tool — it creates request folders only, not `inputs/` subdirectories.
- Changes to `move-request-artifacts.py` or `close-request.py` — neither references the `inputs/` subdirectory.
- Any convention file changes (`analysis-convention.md`, `plan-convention.md`, etc.) beyond what directly reference the archive path.

### Industry Knowledge

**1. Flat artifact layouts in audit trail systems (BABOK, ISO/IEC 15504):**
Audit trails that store per-execution artifacts alongside the primary artifact they document benefit from co-location at a common scope level. Storing the input archive at the same directory level as `analysis-*.md` and `plan-*.md` creates a cohesive request folder structure where all artifacts are directly enumerable without subdirectory traversal. This pattern is preferred in lightweight document-management systems where discoverability and tool simplicity outweigh complex hierarchical organisation.

**2. Unix philosophy and flat-by-default conventions:**
Standard Unix tooling and Python's `pathlib` operate most predictably on flat directory structures for simple artifact stores. Subdirectories add nesting complexity only when justified by volume or category isolation. For request folders containing 3–5 artifacts, a `inputs/` subdirectory serves no classification purpose beyond grouping "received" vs "generated" content — a distinction that naming conventions (`input-archive-*` prefix) already provide without a directory hierarchy.

**3. pytest and test path fixtures:**
In pytest test suites, paths used in assertions are most reliable when they are direct children of the test workspace root or well-known sibling folders. Deep path assertions (`/ "requests" / "R-xxx" / "inputs" / "file.md"`) require more maintenance across test refactors than shallower ones. Reducing nesting from three levels to two levels reduces assertion complexity and the likelihood of off-by-one path errors.

### Edge Cases

- **Attachments with subdirectory structure:** When `.aib_memory/attachments/` contains nested subdirectories (e.g., `attachments/diagrams/schema.png`), the relative path (`diagrams/schema.png`) must be preserved at `<request-folder>/diagrams/schema.png` after the change. The current code uses `dest.parent.mkdir(parents=True, exist_ok=True)` which already handles this correctly by creating subdirectories under `inputs_dir`; after replacing `inputs_dir` with `request_folder`, `dest.parent.mkdir()` will create `<request-folder>/diagrams/` as needed. No additional logic required.
- **`request_folder.mkdir()` no-op:** `create-request.py` always creates the request folder before `finalize-input.py` is invoked. Calling `request_folder.mkdir(parents=True, exist_ok=True)` after the change is a no-op. The `exist_ok=True` flag prevents errors, so this is safe regardless of resolution.
- **Stub-equivalent input with no archive:** When input is stub-equivalent, `inputs_dir` is never created in the current code, which is why the test uses `if inputs_dir.exists() else []`. After the change, the test checking for stub-equivalent non-archiving must check the request folder root for absence of `input-archive-*.md` files — and since `request_folder` always exists, the conditional guard pattern must change.
- **No `inputs/` folder for old requests:** Existing closed request folders still have `inputs/` subdirectories. The no-migration constraint means these remain unchanged. GC-01 and GC-04 guards ensure they are never read, but the pattern change in GC-01 from `inputs/input-archive-*.md` to `input-archive-*.md` means the guard now covers both old-style (in `inputs/`) and new-style (at root) archives. This is a broader, not narrower, guard — which is correct.
- **Archive filename collision:** If two finalize runs occur within the same second for the same request, the timestamp-based filename could collide. This pre-existing risk is unchanged by the layout change. Not in scope.
