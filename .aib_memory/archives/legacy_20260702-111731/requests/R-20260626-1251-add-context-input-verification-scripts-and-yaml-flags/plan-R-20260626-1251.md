# Plan — R-20260626-1251

## Goal

Add context and input verification scripts and YAML flags to AIB's format-integrity infrastructure. This request creates `verify-input.py` (full YAML + body + Q-block validation scope), creates `input-convention.md` as the formal `input.md` specification, adds four top-level YAML verification flags to `input.md`, wires both verification scripts into `aib-analyze.md` and `menu.py`, and extends all supporting tools (`common.py`, `input-header.py`, `finalize-input.py`, `initialize.py`) to handle the new flags.

Impacted components: `.aib_brain/tools/verify-context.py`, `.aib_brain/tools/common.py`, `.aib_brain/tools/input-header.py`, `.aib_brain/tools/finalize-input.py`, `.aib_brain/tools/initialize.py`, `.aib_brain/tools/menu.py`, `.aib_brain/prompts/aib-analyze.md`, `.aib_brain/conventions/` (new `input-convention.md`), `.aib_brain/tools/` (new `verify-input.py`), `tests/` (new `test_verify_input.py`), `.aib_memory/context.md`.

## Constraints

- All scripts MUST use Python standard library only; no third-party dependencies.
- `aib-analyze.md` modifications MUST NOT alter its section-order or break existing step semantics beyond the new S01.1a insertion.
- Four new YAML flags MUST be top-level keys (flat structure) in `input.md` YAML frontmatter, not nested.
- `parse_input_header` backward-compatible defaults: enabled flags → `True` (Python bool), result flags → `None`, for any `input.md` file missing these keys.
- `verify-context.py` check logic MUST remain unchanged; only result-write and `--workspace` argument handling are added.
- `aib-analyze.md` is a `.aib_brain/` file; modification is authorized because this request explicitly authorises it (per `instructions.md` README directive).
- Tests MUST follow the existing `tests/test_verify_context.py` pattern and run with `python -m pytest tests/`.

## Success criteria

- `python .aib_brain/tools/verify-input.py --workspace .` exits 0 when `input.md` is fully conformant and exits 1 on any violation, with failing check names and corrective text printed.
- `python .aib_brain/tools/verify-context.py --workspace .` writes `context_verification_result: valid` or `invalid` to `input.md` YAML header after completing its 10 checks.
- `python .aib_brain/tools/input-header.py --workspace . --operation read` outputs all eight YAML fields including the four new verification flags.
- `python .aib_brain/tools/input-header.py --workspace . --operation write --input-verification-enabled false` successfully writes the flag value to `input.md`.
- `python .aib_brain/tools/finalize-input.py --workspace . --request-id <any>` produces an `input.md` reset containing all eight YAML fields.
- Running `aib-analyze.md` with a non-conformant `input.md` halts with a per-check error message and fix suggestion before any analysis steps execute.
- Running `aib-analyze.md` with a conformant `input.md` proceeds normally without error.
- `menu.py` shows `verify_input` and `verify_context` entries only when their respective enabled flags are `true`.
- `python -m pytest tests/` passes all tests including the new `test_verify_input.py` suite.
- `context.md` contains corrected and extended Solution and Requirements statements as specified in Task 10.

## Plan

### Task 1: Create input-convention.md

#### Intent
Create `.aib_brain/conventions/input-convention.md` as the formal specification for `input.md` format rules that `verify-input.py` will enforce and future maintainers will use as authoritative reference.

#### Procedure

Create `.aib_brain/conventions/input-convention.md` as a new file. The document MUST cover:

- YAML frontmatter schema section: list all eight required top-level keys (`request_id`, `title`, `state`, `options.minimum_questions`, `input_verification_enabled`, `input_verification_result`, `context_verification_enabled`, `context_verification_result`), their types, and allowed values (state: `idle|analysis_ready|questions_generated`; result flags: `null/valid/invalid`; enabled flags: boolean true/false; minimum_questions: non-negative integer).

- Allowed H2 body sections section: enumerate the three permitted headings (`## Input`, `## Options`, `## Questions`) and state that no other H2 headings are allowed.

- Conditional presence rule: `## Questions` MUST be present when `state` is `questions_generated`.

- Q-block format section: reference `q-block-convention.md` as the authoritative source for Q-block format rules; state that each Q-block in `## Questions` MUST conform to that convention.

- Validation check list section: enumerate the checks that `verify-input.py` performs, mirroring the check names that the script will use.

### Task 2: Assess and update verify-context.py

#### Intent
Confirm `verify-context.py` 10-check coverage is current and add `--workspace`-driven result-write capability so the script writes `context_verification_result` to `input.md` after completing checks.

#### Procedure

Open `.aib_brain/tools/verify-context.py`. Confirm the `ALL_CHECKS` list contains exactly 10 functions matching the `context-convention.md` Quality Gates. No check logic changes are needed.

Add `--workspace` argument to the script's argument parser (it may already accept this; if so, verify it is actually used to locate `input.md`).

After the all-checks execution loop, add logic to write the result to `input.md`: if all checks pass, write `context_verification_result: valid`; if any check fails, write `context_verification_result: invalid`. Use `parse_input_header` and `write_input_header` from `common.py` for the read-modify-write cycle.

### Task 3: Create verify-input.py

#### Intent
Create `.aib_brain/tools/verify-input.py` following the `verify-context.py` structural pattern, validating `input.md` YAML header, body sections, and Q-block format, and writing `input_verification_result` to `input.md` after completion.

#### Procedure

Create `.aib_brain/tools/verify-input.py`. The script MUST:

- Accept `--workspace` argument (path to workspace root; default `.`).

- Define an `ALL_CHECKS` list of check functions, one per rule in `input-convention.md`. Required checks:
  - YAML frontmatter present (file starts with `---` delimiter).
  - All eight required top-level keys present.
  - `state` value is one of `idle`, `analysis_ready`, `questions_generated`.
  - `options.minimum_questions` is a non-negative integer.
  - `input_verification_enabled` and `context_verification_enabled` are booleans.
  - `input_verification_result` and `context_verification_result` are one of `null`, `valid`, `invalid`.
  - Only allowed H2 sections (`## Input`, `## Options`, `## Questions`) are present in the body.
  - `## Questions` section is present when `state` is `questions_generated`.
  - Each Q-block in `## Questions` has: a QID line matching the pattern `**Q\d{3}**:`, a `> **Why this matters:**` line, at least one checkbox line `- [ ]` or `- [x]`, and a `- Answer:` or `- Other:` line.

- Run all checks and collect results.

- On completion: use `parse_input_header` + `write_input_header` from `common.py` to write `input_verification_result: valid` (all pass) or `input_verification_result: invalid` (any fail) to `input.md`.

- Exit 0 if all checks pass; exit 1 if any check fails.

- On failure: print each failing check name and a corrective suggestion (e.g., for invalid state: "state must be one of: idle, analysis_ready, questions_generated"; for malformed Q-block: show the expected format line pattern from `q-block-convention.md`).

- Follow the same output format as `verify-context.py`: `[PASS] check_name` or `[FAIL] check_name — <message>`.

### Task 4: Extend common.py YAML header support

Ensure boolean YAML values `true`/`false` are returned as Python `bool` (not the strings `"true"`/`"false"`); result flags `null` must be returned as Python `None`.

Extend `write_input_header` to serialize the four new keys as top-level YAML entries, positioned after the existing four fields, in this order: `input_verification_enabled`, `input_verification_result`, `context_verification_enabled`, `context_verification_result`. Serialize Python `True`/`False` as YAML `true`/`false`; serialize Python `None` as YAML `null`.

### Task 9: Create tests for verify-input.py

#### Intent
Create `tests/test_verify_input.py` covering all check categories of `verify-input.py`, following the `tests/test_verify_context.py` pattern.

#### Procedure

Create `tests/test_verify_input.py`. The test file MUST include test cases for:

- All-pass scenario: a fully conformant `input.md` with all eight YAML keys, valid state, valid section structure, and well-formed Q-blocks results in exit code 0 and `input_verification_result: valid` written to `input.md`.

- Missing YAML frontmatter: `input.md` with no `---` delimiter causes the frontmatter-present check to fail, exit code 1, and `input_verification_result: invalid` written.

- Missing `## Questions` when `state: questions_generated`: causes the conditional-presence check to fail.

- Malformed Q-block: missing `> **Why this matters:**` line or missing `- Answer:` or `- Other:` line causes the Q-block format check to fail with expected format hint.

- Non-boolean enabled flag (`input_verification_enabled: maybe`): causes the boolean check to fail.

- Invalid result flag value (`input_verification_result: unknown`): causes the result-flag check to fail.

Follow the same fixture/tmp-directory pattern used in `test_verify_context.py` (write a temporary `input.md` file, invoke the script via subprocess, assert exit code and output content).
