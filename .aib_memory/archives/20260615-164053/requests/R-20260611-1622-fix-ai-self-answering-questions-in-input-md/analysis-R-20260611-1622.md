# Analysis: R-20260611-1622

## Overview

- **Request ID:** R-20260611-1622
- **Request title:** Fix AI self-answering questions in input.md

### Background

After a completed `aib-analyze.md` run, the developer observed that the `## Questions` section in `input.md` contained at least one Q-block that appeared answered before the developer interacted with it (a checkbox marked `[x]`, or the `- Answer:` field populated with non-placeholder content). The AIB invariant is that Q-blocks written to `input.md` during step S08 must arrive in a fully unanswered state; only the developer may mark answers. The developer requests identification of the bug source in `aib-analyze.md`, `analysis-convention.md`, or `context.md`, plus a minimal-token fix suggestion.

### Scope

- Propose a minimal textual fix in the identified file(s).

### Out of scope

- Changes to `q-block-convention.md` beyond what the developer's scope statement permits.
- Changes to test files, CI workflows, or any non-AIB-memory artifact.
- Refactoring of unrelated prompt logic.

## Research Results

### Workspace pattern-scan

**Finding 1 — `aib-analyze.md` S08 rules block (lines ~210–218)**

Step S08 rules state only:
- "Multiple-choice is preferred when bounded options exist."
- "Use free-text only when the answer space is unbounded."

No rule in S08 prohibits the AI from writing `[x]` on any option or populating `- Answer:` with non-placeholder content. This is a permissive-by-omission gap: the agent has no explicit constraint against expressing a pre-selected answer when generating Q-blocks for `input.md`.

**Finding 2 — `analysis-convention.md` section 4.5 "Resolution outcome" (line ~87)**

The Decision Register convention states:

> `- Resolution outcome: retain only chosen alternative; discard non-chosen from final doc`

This instruction appears in the general DP block without qualifying which DP states it applies to. For `resolve-autonomously` and `resolved-by-user` DPs it is correct: the analysis document retains only the chosen alternative. For `ask` DPs — where no alternative has been chosen — the rule is undefined. An AI agent may interpret "retain only chosen alternative" as requiring selection even for `ask` DPs, and carry that selection into the Q-block by marking the option `[x]`.

**Finding 3 — `aib-analyze.md` S08.1 promotion scenario**

When S08.1 promotes a DP from `resolve-autonomously` to `ask` (because [Questions-expected] exceeds the number of `ask` DPs), the promoted DP already has a "chosen alternative" recorded in the analysis from its original `resolve-autonomously` phase. Step S08.2 then generates a Q-block for this promoted DP. No rule prevents the AI from treating the pre-existing choice as the answer and writing `[x]` next to it in the Q-block.

**Finding 4 — Conflict: analysis-convention.md "AI MUST NOT express preference" vs q-block-convention.md *(recommended)***

`analysis-convention.md` 4.5 states for `ask` DPs: "AI MUST NOT express preference or steer toward any option; present choices neutrally." However, `q-block-convention.md` requires "exactly 1 option marked *(recommended)* as AI's preferred choice." These rules conflict. When an AI resolves the conflict, one failure mode is marking the *(recommended)* option `[x]` to simultaneously satisfy both constraints (expressing preference through selection rather than just a text marker).

**Finding 5 — `context.md`**

No entry in `context.md` references Q-block generation behavior or the answered/unanswered state of Q-blocks. `context.md` is not a source of this bug.

### Industry knowledge

1. **Form generator responsibility (Nielsen Norman Group — Form Design Best Practices):** A form generator must never pre-complete fields on the responder's behalf unless explicitly pre-filling from previously saved data. Generating a selection form with a pre-checked option conflates the roles of "form designer" and "responder." The AIB Q-block generation step plays the role of form designer; the developer plays the role of responder. The bug arises when the generator role bleeds into the responder role. Applicability: directly applicable; S08.2 needs an explicit postcondition asserting all checkboxes remain `[ ]`.

2. **Precondition-postcondition contracts (Design by Contract — Bertrand Meyer):** Each procedural step should have explicit postconditions that constrain its outputs. S08.2 currently has no postcondition asserting "all written Q-blocks MUST be unanswered." Adding one postcondition rule eliminates the ambiguity with minimal token cost. Applicability: directly applicable and is the minimum viable fix pattern.

3. **Fail-safe defaults (OWASP Secure Coding Practices):** Systems should default to a safe state; a "no decision made" default is safer than a pre-selected one. For Q-blocks, the safe default is "unanswered" (`[ ]`). The absence of an explicit "default = unanswered" rule in the generation step is a security-of-process gap that matches this principle. Applicability: applicable as a framing argument for why the fix belongs in S08 rather than relying on the AI's inference.

### AI Agent critique

- `aib-analyze.md` S08 rules: permissive by omission — no "MUST NOT pre-check any option; MUST NOT populate `- Answer:`" constraint.
- `analysis-convention.md` 4.5 "Resolution outcome": ambiguous scope — does not exclude `ask` DPs; AI may pre-select for `ask` DPs.
- `analysis-convention.md` 4.5 "AI MUST NOT express preference" applies to the analysis document, not explicitly to Q-blocks in `input.md`; the boundary of its scope is unclear.
- `aib-analyze.md` S08.1 promotion: DPs promoted from `resolve-autonomously` carry a pre-chosen alternative; no rule prevents that choice from appearing as `[x]` in the generated Q-block.
- `analysis-convention.md` "AI MUST NOT express preference" contradicts `q-block-convention.md` "exactly 1 option marked *(recommended)*"; this conflict may induce the AI to resolve the tension by marking `[x]`.
- `context.md`: no Q-block-generation content; confirmed non-source.
- `q-block-convention.md`: correct format spec but lacks a "never pre-answer" rule; this is a quality gap in a file outside the developer-specified scope.

## Decision Register

### Decision Points

#### Decision Point: Primary bug file identification
- Tag: `ask`
- Rationale: Two files contain contributing defects. `aib-analyze.md` S08 is missing an explicit "MUST NOT pre-answer" constraint (permissive by omission). `analysis-convention.md` section 4.5 contains an ambiguous "Resolution outcome" instruction that does not exclude `ask` DPs (ambiguity by omission). Identifying which is the **primary** source requires developer judgment, as both independently enable the bug.
- Alternative A: `aib-analyze.md` S08 is the primary source — the generation step has no guard.
  - Trade-offs: fixing here is closest to the failure point; a single rule addition prevents the bug regardless of convention ambiguity.
  - Impact: change to `aib-analyze.md` only.
- Alternative B: `analysis-convention.md` section 4.5 is the primary source — the "Resolution outcome" instruction ambiguously applies to `ask` DPs.
  - Trade-offs: fixing here removes the root semantic ambiguity; the AI would never pre-select for `ask` DPs.
  - Impact: change to `analysis-convention.md` only.
- Alternative C: Both files are co-equal sources — neither alone would be a sufficient fix.
  - Trade-offs: most complete fix; slightly higher token cost (two files touched).
  - Impact: changes to both `aib-analyze.md` and `analysis-convention.md`.

#### Decision Point: Fix location
- Tag: `ask`
- Rationale: Depends on the primary source identification. If Alternative A above is chosen, fix goes to `aib-analyze.md`. If B, fix goes to `analysis-convention.md`. If C, fix goes to both. Each has different token cost.
- Alternative A: Fix only `aib-analyze.md` — add one constraint line to S08 rules.
  - Trade-offs: minimal token addition; does not repair the convention ambiguity.
  - Impact: one line inserted in `aib-analyze.md`.
- Alternative B: Fix only `analysis-convention.md` — qualify "Resolution outcome" to exclude `ask` DPs.
  - Trade-offs: addresses root semantic cause; leaves S08 without an explicit guard.
  - Impact: one-line modification in `analysis-convention.md`.
- Alternative C: Fix both files.
  - Trade-offs: most robust; adds ~2 short lines total.
  - Impact: one change in each file.

#### Decision Point: S08.1 promotion scenario coverage
- Tag: `ask`
- Rationale: The S08.1 promotion scenario (DP promoted from `resolve-autonomously` to `ask`) is a distinct failure path from the general "missing guard" path. It is caused by the promoted DP retaining its original chosen alternative when a Q-block is generated. Whether the fix should explicitly address this scenario is a scope question.
- Alternative A: Fix covers the general case only — add "MUST NOT pre-check" to S08.2; promotion scenario is implicitly covered.
  - Trade-offs: simpler; relies on the general guard catching the promotion scenario.
  - Impact: no additional change needed.
- Alternative B: Fix explicitly addresses the promotion scenario — add a rule to S08.1 that strips the "chosen alternative" from the DP before it becomes `ask`.
  - Trade-offs: explicit; eliminates the ambiguity at the promotion step itself.
  - Impact: one-line addition to S08.1.

#### Decision Point: Wording of the fix
- Tag: `ask`
- Rationale: The exact language of the fix must be minimal-token and unambiguous. Multiple phrasings exist; developer approval is needed.
- Alternative A (for `aib-analyze.md` S08 rules): `- MUST write all Q-blocks unanswered: all checkboxes \`[ ]\`; \`- Answer: ___\` verbatim; MUST NOT mark \`[x]\` or populate Answer fields.`
  - Trade-offs: explicit and complete; adds ~15 tokens.
  - Impact: one bullet added to S08 rules block.
- Alternative B (for `analysis-convention.md` 4.5 "Resolution outcome"): Change `- Resolution outcome: retain only chosen alternative; discard non-chosen from final doc` to `- Resolution outcome [resolve-autonomously|resolved-by-user]: retain chosen, discard others; [ask]: !select; retain all alternatives`
  - Trade-offs: uses existing compact notation; adds minimal tokens; fixes the semantic ambiguity.
  - Impact: one line replaced in `analysis-convention.md`.
- Alternative C: Both A and B applied together.
  - Trade-offs: maximum clarity; minimal combined token cost (~25 tokens total).
  - Impact: changes to both files.

#### Decision Point: context.md update
- Tag: `ask`
- Rationale: `context.md` is not a source of this bug, but the product requirement "Q-blocks written to `input.md` must be unanswered" is not explicitly represented as a functional requirement (`R:` entry). The developer's "minimal token usage" constraint suggests caution about adding unnecessary content.
- Alternative A: Add a functional requirement entry to `context.md` — `- R: AIB MUST write all Q-blocks to input.md in unanswered state; AI MUST NOT pre-check options or populate Answer fields.`
  - Trade-offs: improves context completeness; adds ~20 tokens; broadens convention awareness.
  - Impact: one entry added to `context.md ## FN`.
- Alternative B: Do not update `context.md` — the fix in `aib-analyze.md` and/or `analysis-convention.md` is sufficient.
  - Trade-offs: minimal token cost; context remains without this explicit rule.
  - Impact: no change to `context.md`.
