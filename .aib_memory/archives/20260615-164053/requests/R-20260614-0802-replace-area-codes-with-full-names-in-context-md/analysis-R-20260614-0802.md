# Analysis: R-20260614-0802

## Overview

**Request ID:** R-20260614-0802
**Request title:** Replace area codes with full names in context.md

### Background

The context subsystem currently uses abbreviated 2-letter identifiers (e.g., `## FN`, `## TD`) as H2 section headings in both context.md and the context-convention.md that governs it. These codes are opaque to any reader who has not memorised the lookup table, adding unnecessary cognitive load when navigating or editing context.md manually. Separately, context.md (Product Identity section and the TS area) claims that "Git" is a required AIB runtime dependency. Research confirms this is incorrect: all core AIB Python tool scripts use only the Python 3 standard library and make no git CLI calls. Only the optional CI release-bookkeeping script (`scripts/release_bookkeeping.py`) invokes git, and that script runs exclusively in a GitHub Actions environment — it is not part of the core AIB workflow.

### Scope

- Replace all 22 two-letter area code identifiers with their full English names in `context-convention.md` (definition), `context.md` (content headings), `verify-context.py` (validation), and `edit-context.py` (CRUD tooling).
- The `--area` CLI argument of `edit-context.py` is updated to accept full area names (e.g., `--area Functionality`).
- Correct two factually incorrect statements in `context.md` that list Git as a runtime dependency.
- Update quality gate #3 in `context-convention.md` and associated error messages in the tool scripts to reference full area names.
- Update test fixtures in `tests/test_verify_context.py` and `tests/test_context_formatting_rules.py` that hardcode 2-letter area codes.

### Out of scope

- Statement type identifiers (N, R, C, D, I, etc.) — unchanged.
- `scripts/release_bookkeeping.py` — its git dependency is legitimate (CI automation) and is explicitly excluded.
- `.github/` CI workflow configuration files — no runtime dependency claim exists there.
- `docs/Development_and_Deployment_Specification.md` — accurately documents the AIB development/release workflow (which uses Git) and contains no incorrect runtime dependency claim.
- `user_guide.html` — already correctly lists Python 3.10+ only as prerequisite; no change needed.
- `aib-refresh-context.md` prompt — its `.git/` exclusion pattern is a workspace scan setting, not a runtime dependency.
- Context.md references to GitHub Actions for CI (CM and DV areas) — factually correct; retained.

### Industry Knowledge

1. **Self-documenting section identifiers (DITA, DocBook, AsciiDoc):** Industry-standard documentation frameworks (DITA Topic Types, DocBook XML sections, AsciiDoc section names) consistently use full English words as section identifiers, not abbreviations. The DITA specification defines topics as `concept`, `task`, `reference` — never `C`, `T`, `R`. The rationale is that full names are self-describing and eliminate the need to consult a legend. Applicability: directly applicable; AIB context.md sections are analogous to topic sections in a documentation framework.

2. **Separating optional automation from core runtime dependencies (Twelve-Factor App, npm devDependencies pattern):** The Twelve-Factor App methodology (factor II — Dependencies) states that an application must explicitly declare all dependencies and distinguish runtime deps from build/CI deps. npm formalises this as `dependencies` vs. `devDependencies`. pip projects use `requirements.txt` vs. `dev-requirements.txt`. AIB's git usage in CI is equivalent to a devDependency — not required to run the product, only to release it. Applicability: directly supports correcting the runtime dependency claim in context.md.

3. **Single Source of Truth for validation rules (DRY principle, SSOT pattern):** When a validation rule (e.g., the set of valid area names) is encoded in both a human-readable convention file and a machine-executable script, they must be kept in sync. OSS projects routinely generate the code constant from the authoritative source (e.g., JSON schema → generated TypeScript enum). AIB's current approach of duplicating VALID_AREAS in two Python files against context-convention.md is a known maintenance risk. Applicability: the rename is an opportunity to verify all three sources are in sync; future drift should be monitored by the test suite.
