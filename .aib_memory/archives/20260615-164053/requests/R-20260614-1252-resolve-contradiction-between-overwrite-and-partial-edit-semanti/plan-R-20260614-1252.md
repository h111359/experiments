## Goal

Resolve the contradiction between overwrite and partial-edit semantics in the analysis workflow so rerunning analysis is deterministic and convention-aligned. The change is needed because [analysis-convention.md](.aib_brain/conventions/analysis-convention.md) mandates full replacement of active analysis artifacts while [aib-analyze.md](.aib_brain/prompts/aib-analyze.md) currently contains partial-edit instructions in S05.2.2 and S05.3.2. Impacted components are the analysis prompt specification, related convention wording if needed for clarity, and validation tests/documentation that enforce analysis-run behavior.

## Constraints

- Preserve normative intent in [analysis-convention.md](.aib_brain/conventions/analysis-convention.md): re-run semantics must remain full overwrite, not append/prepend/partial edit.
- Keep all changes deterministic and text-traceable; avoid introducing new behaviors outside the stated contradiction fix.
- Restrict implementation scope to files required to remove the semantic conflict and keep tests green.
- Maintain compatibility with existing request lifecycle rules and artifact naming/location conventions.

## Success criteria

- [aib-analyze.md](.aib_brain/prompts/aib-analyze.md) contains no instruction that allows partial line edits of existing analysis content during re-run.
- [analysis-convention.md](.aib_brain/conventions/analysis-convention.md) and [aib-analyze.md](.aib_brain/prompts/aib-analyze.md) express consistent overwrite semantics.
- Relevant tests pass using `python -m pytest tests/` with no regression in prompt/convention validation behavior.
- [context.md](.aib_memory/context.md) is updated through explicit `edit-context.py` command(s) to capture the resolved overwrite semantic rule.
